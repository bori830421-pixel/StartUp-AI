一个面向创业新手的 AI 技能。你说出想做的方向和手里的钱，它先判断「现在该不该开始」；判断可以做，才进入分阶段陪跑，帮你把第一笔钱挣到。

## 它解决什么问题

新手最缺的不是更多的分析，而是一句能信的判断。

但「你成功的概率有多大」这个问题没有任何诚实的方式能回答。所以本技能不预测结果，只检查条件：启动这件事需要的东西，你现在满足几项。

```text
阶段一 体检 → 闸门 → 阶段二 陪跑
```

体检不过，就没有陪跑。这是设计上的硬约束，不是建议。

## 当前状态

规则与接入框架阶段。已有规则、能力边界、38 个验收场景、28 个行为样例，以及三种可安装形态（目录技能 / 单文件 / MCP）。除 `tools/` 下的版式引擎、构建校验与 MCP 服务端外，没有数据库、后端或外部服务集成。

可安装：仓库不是安装单元，`dist/startup-guide/` 才是。它已入库，克隆即可用，不必先装 Python；改了源文件才需要重建。

python tools/build_flat.py      # 重建单文件形态 dist/startup-guide.flat.txt

三种形态都已支持：目录技能（首选）、单文件注入（只有对话框的宿主）、MCP（`tools/mcp_server.py`，零依赖）。装法与验证见 [INSTALL.md](./INSTALL.md)，各形态细节见 [hosts/](./hosts/README.md)。

## 怎么用

1. 读 `SKILL.md` 了解两阶段结构和闸门规则。
2. 看 `examples/06`、`07`、`08`、`11`，对照正式放行、条件放行、当前版本不建议启动，以及“暂缓投入、局部门槛待核验”四种输出。
3. 看 `examples/15` 和 `16`，理解「只读卡片」「跑检索循环」「断网降级」三种输出的差别——前两种是能力问题，第三种是环境问题，但都不能把卡片当成查过。
4. 需要具体口径时查 `references/` 下的文件；检索流程与查询串见 `runtime-loop.md` 和 `search-playbook.md`，断网见 `offline-degradation.md`。
5. 要出 PPT 时看 `references/deck-spec.md`（页序与每页必须成立的判断）与 `tools/README.md`（一条命令出文件）；不想装 Python 也能用，降级形态在 `deck-spec.md` 第 6 节。

## 部署（要出 PPT 才需要）

双击项目根目录的 **`setup.bat`**。通常可离线部署；若本地 wheel 与 Python 版本不兼容，脚本会提示并联网重试：

```text
setup.bat  →  找 Python → 建 .venv → 离线装依赖 → 冒烟测试 → 环境体检
make-ppt.bat tools\briefs\01-chenghai-zhaoyiming.json 输出.pptx
```

依赖 wheel 已随仓库提供（`tools/wheels/`，27.2 MB），所以克隆即可离线部署。基础出稿只需要 Python 3.9+ 和 python-pptx；默认 `setup.bat` 不安装 PDF 检查依赖。PDF 转换与几何检查环境配置可能比较繁琐，默认建议跳过；用户明确需要时运行 `setup.bat --with-pdf-check`，再用 `python tools/doctor.py --pdf` 实测。PowerPoint、LibreOffice、WPS 需另行安装，不影响 PPTX 出稿。

细节与踩过的坑见 [tools/README.md](./tools/README.md)。

## 判断分四档

| 结果 | 条件 | 后续 |
| --- | --- | --- |
| 放行 | 三个硬门槛全过，软约束最多 1 项偏弱 | 直接进入 P1 接触 |
| 有条件放行 | 硬门槛全过，软约束 2 项及以上偏弱 | 先补短板，复核通过再进 P1 |
| 暂缓当前投入 | 硬门槛仍缺证据或待现场核验，尚无证据证明当前方向失败 | 不签约、不付不可逆费用；算出已知场景，给一个可改变判断的核验动作，不进入陪跑 |
| 不建议按当前版本启动 | 证据表明硬门槛不通过，或所有合理场景都越不过用户风险线 | 说明当前店型/规模/资金结构的问题，给最小代价出口，不外推成整个行业失败 |

三个硬门槛是客户可达、现金流断点、合规前置。四个软约束是资金、时间、能力、可逆性，只用来排序和找短板，不求和——总分会把否决项稀释成可接受的扣分。

公开参数缺失时先检索并做有来源标签的情景；具体门槛未核实时不放行，但仍给当前投入立场和能改变判断的动作。不能把局部信息不足扩大成整份评估无结论，也不能把估算写成已证明可行。

## 判断依据从哪来

不做「行业很大所以能做」这类推理。这个技能也不是脱离网络自问自答——它每次都会按生意原型生成检索计划，从网上取当前的政策、成本与平台规则，再判断。

依据分三层，混用是片面的根源：

| 层 | 来源 | 怎么用 |
| --- | --- | --- |
| 结构 | 原型卡 | 成本比例、现金流节奏、哪项刚性、通常怎么死。**不搜**，这类知识稳定 |
| 参数 | 检索加情景，再核验 | 客流、客单价、房租、单量。地区已知时先查范围并计算低中高场景；只有结论敏感的本地变量需要现场替换 |
| 事实 | 官方原文 | 证照要求、办理周期、处罚标准、平台规则。**必须打开原文**，不能只看摘要 |

一句话：**结构靠推演，参数先检索估算、关键项再实测，事实靠原文。**

检索有预算：线上必查项 × 2，上限 12 个查询，查完就出结论。线下必查项不占预算，转成用户动作。宁可交一份标注了空缺的判断，也不要搜十轮拼一个看起来完整的答案。

**没有联网能力时它会先说。** 判定离线、把缺的信息说清、给「你开联网 / 你自己查」两条路；受影响门槛挂起、不提供启动放行，但仍算可算项并给当前投入立场。不会把卡片里的旧内容包装成「我查了一下」。规则见 `references/offline-degradation.md`。

行业数据按四级标注，级别决定它能不能进判断：

| 级别 | 内容 | 能否进判断 |
| --- | --- | --- |
| L1 结构级 | 成本结构比例、现金流节奏、常见死法 | 可以，标结构性判断 |
| L2 区间级 | 客单价、毛利、启动资金区间 | 只作范围参考，须标日期与口径 |
| L3 事实级 | 政策条款、证照要求、平台规则 | 必须现场核实，不替代官方查询 |
| L4 传闻级 | 自媒体统计、招商宣传、加盟广告 | 不能进判断，只能当线索 |

招商加盟平台、品牌方、培训机构的数据属于利益相关来源，一律打折。规则见 `data/source-grading.md`。

## 设计原则

- 区分事实、估算、假设、待核实四类信息，不把预测包装成事实。
- 不虚构市场规模、成本、法规或成功率；动态信息注明来源与日期。
- 判断必须挂在分项上。不给无依据的结论，也不给「都可以，看你」。
- 卡片划边界，搜索填内容。静态卡片只决定搜什么、怎么判，不提供结论；缓存过期就只当检索起点。
- 零启动资金方案必须披露隐性成本，不把「无现金」写成「无成本」。
- 陪跑一次只给一个阶段。新手看完完整计划会以为自己懂了，然后什么都不做。

## 边界

本技能提供结构化分析与规划辅助，不替代投资、法律、税务或监管判断。涉及这些领域时，提示用户按所在地向专业人士确认。
