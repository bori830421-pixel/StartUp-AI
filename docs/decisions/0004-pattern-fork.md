# 决策记录 0004：模式分叉前置

- 状态：已采纳
- 日期：2026-10-28

## 背景

技能在电商案例上给出了错误判断：把「5000 元做电商」判为「够测款，不够开店卖货」。

用户指出问题所在：1688 上有大量客单价 10 元级别的货源，无货源代发模式下货款在成交后才支付，2000 元就够启动。5000 元不仅够，而且宽裕。

根本原因不是算术错，是**前提错**：技能默认了「有货源自备货」这一模式，把该模式的成本结构当成了类目的成本结构。

## 决定

1. **模式分叉前置到体检之前。** 流程改为「方向 → 类目匹配 → 模式分叉 → 七维体检 → 闸门」。
2. **分叉后必须重算分项，不能只改结论。** 只改结论是假闸门的另一种形态。
3. **默认推荐最轻的模式**，且模式可以升级、不可以跳级。
4. **每轮输出必须以「下一步唯一动作」结尾。** 只给判断不给动作，等于没有引导。
5. **平台选择改为推导，不给清单。** 先定客单价带，再反推平台。

## 理由

**为什么这是结构性错误**：技能已有的判断逻辑本身没错，错在输入的成本结构。同一预算在不同模式下缺口可能相差数倍，模式选错，七维体检的分数全部失真。

这类错误不只出现在电商。餐饮有堂食与纯外卖之分，家政有员工制与中介制之分，都是同一结构。所以修法不能只修电商档案，要变成通用流程。

**为什么要「下一步唯一动作」**：用户指出技能「没有起到引导作用」。判断正确但停在判断，新手会原地不动。引导的定义是「判断 + 一个可执行的动作」，不是「判断 + 一堆建议」。

**为什么平台要推导不能给清单**：给新手三个平台让他选，他会选听起来最轻松的那个，而最容易的平台往往竞争者最多。

## 后果

- 新增 `references/pattern-fork.md`，规定分叉位置、各类目分叉、对体检四项的影响、三条纪律。
- `SKILL.md` 流程插入第 4 步「模式分叉」，原体检与判断顺延；新增第 7 步「下一步唯一动作」，明确四种结论各对应什么动作。
- `data/industries/03-shelf-ecommerce.md` 重写第 1 节为模式分叉，成本结构按模式分列，新增平台选择一节，修正体检要点中的 S1 与 H2 算法。
- `references/checkup-scorecard.md` 的 S1 增加「必须按模式算」。
- `examples/10-budget-ladder.md` 重写，从「加钱不改变瓶颈」改为「先分模式再算钱」。
- 验收场景新增「模式未分叉」与「体检后无下一步动作」两项。
- 后续每个新档案卡都必须在第 1 节列模式分叉，否则视为不合格。
