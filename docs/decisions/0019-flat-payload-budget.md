# 0019 单文件形态：体积由脚本现算，载荷只收运行时指令

- 状态：已采纳（修订 0015 的「全量收录」与体积口径）
- 日期：2026-10-30

## 背景

`docs/capability-index.md` 与 `README.md` 一直写着 B 形态「token 实测约 12,600，32k 占 38.5%」，并挂着一条欠账「加了检索兜底后 token 未复跑」。实际复算发现三个问题：

1. **数字是旧的。** 12,600 是 4 份 references 时的实测值。0015 加检索兜底后，自己在「后果」里估了 15,300，但这个数字没进任何对外文档，文档停在 12,600。
2. **估算方法也偏了。** 0015 用「中文约 1.6 字/token」，把含大量 ASCII 与 Markdown 标记的整份文件按纯中文算，系统性低估。按汉字 1 token、非汉字 4 字符/token 估，改前约 18,300；用唯一一次真实测量（17,857 字符 ≈ 12,600 token）反推，量级一致。
3. **手写数字必然漂。** 每次改 `references/` 都要重建 flat，体积随之变，但文档里的数字没人会记得同步——这不是疏忽，是口径设计错了。

## 决定

1. **体积由 `build_flat.py` 现算并打印**：生成时输出 token 估算与 8k / 32k / 128k 三档占用，文档只写「约多少、脚本现算」，不再手抄精确值。
2. **载荷只收运行时指令**：源文件里用 `<!-- flat:skip -->` / `<!-- flat:skip-end -->` 圈出「给维护者看、不改变模型行为」的段落，拼接时机械剔除。本次剔除两处：`SKILL.md` 的「详细索引」（flat 里是死链与维护者信息）、`search-fallback.md` 的「实测记录」（证据，不是指令）。
3. **8k 宿主明确不支持**，不再写成「未验」。改后约 17,230 token，32k 占 53%。

## 理由

- **用标记而不是在构建脚本里写行号。** 行号会随源文件改动错位，标记不会；而且标记本身写明了「这段为什么不进载荷」，下一个维护者不用猜。
- **剔除实测记录不等于删证据。** 记录留在 `references/` 里，A 形态照读。flat 是运行时载荷，模型拿着一张「2026-10-30 某台机器上必应返回二手房」的表什么也做不了，只会多占 800 token。
- **候选池不能删。** 曾考虑把国内 / 境外两张端点表也移出（能再省约 1,400 token）。0015 的现场记录否掉了这个想法：那台 DeepSeek 桌面端确实能发起 fetch（DuckDuckGo、Brave 都试过，报 `fetch failed`），只是搜索工具缺 key。候选池正是这种宿主唯一能用的东西。
- **8k 不是「还没测」而是「装不下」。** 规则本身就有 17k 的量级，压到 8k 只能删规则——那等于把技能阉掉换一个能装进去的壳。承认边界比留一条永远消不掉的欠账诚实。

## 后果

- 改 `references/` 后仍必须重跑 `build_flat.py`，`--check` 的字节比对继续兜底。
- 新增「只给维护者」的段落时，记得加标记；不加就进载荷，`build_flat.py` 打印的体积会立刻反映出来。
- 4 处口径同步：`README.md`、`docs/capability-index.md`、`hosts/plain-prompt.md`、`INSTALL.md`（新增「B 形态要求 ≥32k」一段与装不下时的替代做法）。
- **未做**：没有为小上下文宿主做精简版。那会引入第二套真相（同一份规则维护两个版本），与项目一贯口径冲突。宿主装不下时按 `INSTALL.md` 的做法只贴 `SKILL.md` 加评分口径，并说明少了几份材料。
