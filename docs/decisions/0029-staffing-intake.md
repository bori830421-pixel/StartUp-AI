# 0029 用工人数改为「问出」：选项去人数锚点，品类卡加参考用工

日期：2026-11-01。修订 [0027](./0027-intake-9-plus-3.md) 引入的条件 11 采集口径。

## 问题

条件 11 的 A–D 选项自带人数锚点（C 档「雇 1–2 个人」），推断表又用每周投入时长推人数（<10h 推 1–2 人）。这两处都隐含「小门店、老板本人是主要劳动力」的形态：

- 开辅导站、托管站的人自己是主力，按形态该选 B 或 C，但实际要养 5–10 人的队伍——人数锚点把他带偏，或逼他错选 D「完全不参与」。
- 用工密集形态里时长与人数脱钩：托管站老板每周只去几小时也要养一支队伍，按时长推断，H2 的人工分母直接错一个量级，而人工恰恰是这类生意最大的刚性支出。
- 品类卡没有用工参考字段，采集时没有任何核对基准；「人力门槛」只存在于有缓存的卡的缓存元信息里，随缓存过期。

## 决定

1. **选项只回答「谁在干」。** A–D 文字去掉人数锚点：A 自己全职干，基本不请人；B 自己主力，忙时搭把手（请兼职）；C 自己偶尔来，活主要靠请人干；D 完全不参与，全部请人。
2. **人数按三步采集，每一步的数字都必须出自用户**：给参考出追问（按品类卡「参考用工」行给区间，要岗位清单）→ 说不出给低中高三档选一档 → 不代填，没答之前人工项按信息不足挂起。这与「人工成本必须问出口，不能推算」同一条边界，不是推翻它。
3. **品类卡骨架新增「参考用工」字段**：按形态给人数区间，用于条件 11 的核对与追问；区间本身不进 H2。11 张卡全部补行，`_template.md` 同步。
4. **推断表收窄为只推老板位置**：时长 × 形态只说明老板全职在店、主力、偶尔到场还是不参与；人数不在此表，只认用户答出的岗位清单。
5. **偏离不复核对错。** 用户配置与参考区间偏离时，复述他的配置让他确认即可——偏离本身可能就是他的经营计划，照看缺口写进风险，不替用户改计划。

## 改动落点

- `references/intake-questions.md`：条件 11 选项与影响行重写，新增「用工人数必须问出来，不推算」一节；分支表 C 行改为岗位清单。
- `references/cost-discovery.md`：条件题选项同步；推断表改为「推断老板位置 + 人工月成本从哪来」；新增用工密集形态的说明。
- `data/categories/_template.md` 与 11 张品类卡：骨架加「参考用工」行。
- `examples/32-staffing-intake.md`：新增样例（托管站 A 档预期 1 人被 3–8 区间纠偏，最终配置全部出自用户）；`docs/verification-guide.md` 的「用工结构未问」场景改为新口径，样例列加 32。

## 不改的

- 「人工成本必须问出口，不能推算」原样有效，本记录是它的延伸而非替代。
- 参考用工区间是结构信息，不进 `data/params.json`（机器镜像只收判断阈值，见 [0014](./0014-mcp-boundary.md) 的边界）。
- 缓存元信息里已有的「人力门槛」行保留——那是缓存观测记录，与骨架的结构参考生命周期不同。
