# 0022 缺失数据先检索和估算，再判局部门槛

- 状态：已采纳
- 日期：2026-10-31

## 背景

新手通常不知道商铺租金、岗位工资、座位数、翻台率或客单价。旧流程把多个参数设成用户必答或必须实测，导致信息不足被扩大成整份评估停摆。餐饮堂食还缺少桌数/座位、翻台、客单、营业日等经营容量模型。

## 决定

缺失信息先分为四类：用户个人事实少量追问；地区已知的公开动态参数按检索预算主动查询；无平面图或真实销量的模型参数按低、中、高场景估算；具体合同、点位需求、布局许可等必须本地或官方核验。

每个场景标清来源等级、日期、口径、假设和敏感变量。单一来源与 L4 只作线索；可作明确排除在判断依据外的压力测试，不得证明硬门槛通过或不通过。局部信息不足或待核实不放行、不进入陪跑，但必须给当前拟议投入的临时立场、可计算部分和一个能改变判断的核验动作；只有证据已显示当前模式不满足，才判当前版本不建议启动。

堂食模型按桌数/座位、翻台或周转、客单、营业天数估收入容量；外带与外卖按渠道订单另算，并比较所需保本流水。演示稿允许展示初筛场景，但要把事实、检索范围、假设和待核实项分开。

## 理由

- 公开市场参数可以由运行时检索补齐，不应让新手先知道答案才获得帮助。
- 情景范围能给出当前行动判断，也能指出哪项本地证据最值得验证；它不等于实际营业结果。
- 用户的生活支出、风险承受能力、时间偏好等个人事实不能从网络推断。
- 将“当前是否签约投入”与“方向是否已证明可行”分开，既不虚假放行，也不因资料未齐误杀方向。

## 后果

- 需要同步修订引导盘点、成本检索、评分口径、离线降级、餐饮卡、演示文稿规格、MCP 提示词和验收样例；MCP 计算工具仍只执行确定性公式，不承担新的判断。
- 每次运行仍需重新核实动态来源；样例中的测试夹具不能作为真实市场数据复用。
- 闸门继续有效：硬门槛未通过或待核实都不启动陪跑；临时立场不等于放行。
