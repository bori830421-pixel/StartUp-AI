# 决策记录 0006：按原型分类，不按行业分类

- 状态：已采纳
- 日期：2026-10-28

## 背景

用户提出两个问题：

1. 项目要扩展到各行各业（加盟连锁、摆摊、公园卖玩具、自媒体、开工厂、跑滴滴、跑腿），按「一类目一卡」的方式建档不可扩展。
2. AI 能搜全网，但给出的答案片面；而用户作为个体知识储备有限，无法逐条校验。

这两个问题指向同一个根源：**分类维度选错了**。

## 决定

1. **按生意原型分类，不按行业分类。** 建七张原型卡：卖时间、卖货轻库存、卖货重库存、卖技能服务、卖内容注意力、买系统加盟、生产制造。
2. **行业卡降为补充。** 只有在该行业有专门许可、专门平台规则、或成本结构明显偏离原型时才建档，否则直接用原型卡推演。
3. **新增定向检索协议。** 结构靠推演、参数靠实测、事实靠原文。只查原型卡列出的必查项。
4. **原型数量上限十个。** 超过说明分类维度有问题。

## 理由

**为什么行业分类不可扩展**：行业有几千个，且不断细分。一类目一卡，永远补不完，且每张都要人工维护、定期复核。而原型只有七种，覆盖绝大多数个体创业。

**为什么原型能跨行业迁移**：同一原型下，成本结构、现金流节奏、关键约束、失败模式高度相似。跑滴滴和跑美团跑腿是两个行业，但判断逻辑完全一样。摆摊卖小吃和摆摊卖玩具是两个品类，但生死都在点位与备货量。

**为什么片面不是搜得少**：片面的根源是没有框架。不知道该搜什么，就会搜到最会做 SEO 的那些内容——搜「家政创业成本」前排全是招商平台。有框架的搜索是收敛的，只查四到五项，查完就够。

**为什么参数必须实测**：检索到的单价、租金、单量，只能当范围参考。它们地区差异大、时效性强、且常被利益相关方美化。给实测方法比给数字有用。

**为什么必须能劝退**：七个方向里，开工厂、贷款跑滴滴、无备案的加盟，都应该直接说不建议。技能如果只会说「可以做」，就会变成安慰剂。

## 后果

- 新增 `data/archetypes/`：README（识别表与使用流程）+ 七张原型卡。
- 新增 `references/research-protocol.md`：三级检索、反证测试、交叉验证、识别广告、什么时候该说查不到。
- `SKILL.md` 流程插入第 4 步「识别生意原型」，原模式分叉顺延为第 5 步；必须遵守新增两条。
- 新增样例 14：七个方向一次识别完，并明确劝退其中三个。
- 行业档案库从「主库」降为「补充库」，收录标准收紧。
- 后续新增方向的正确做法是：先识别原型 → 用原型卡推演 → 只对特殊项定向检索 → 确实特殊才建行业卡。
