# 决策记录 0002：两阶段结构与体检闸门

- 状态：已采纳
- 日期：2026-10-28

## 背景

技能最初按线性 8 步流程设计（收集 → 探索 → 比较 → 验证 → 启动框架 → 交付）。讨论中确认目标用户是创业新手，而新手最需要的是「我这个条件下到底该不该开始」这一句判断，而不是更长的分析。

同时存在一个设计矛盾：项目规则禁止承诺成功率，但新手拿不到判断就会去问敢承诺的人。

## 决定

1. **评估结果采用 B 方案**：分项得分 + 一句综合判断。判断必须挂在分项上，不换算成成功率或百分比。
2. **两阶段串行，中间设闸门**：阶段一为启动条件体检，阶段二为分阶段陪跑。未通过体检不进入陪跑。
3. **体检用七维口径，不用总分**：三个硬门槛（客户可达、现金流断点、合规前置）单独判定；四个软约束（资金、时间、能力、可逆性）只用于排序和找短板，不求和。理由见下。
4. **判断分三档**：放行、有条件放行、不建议启动。
5. **不建议启动时保留「最小代价出口」**：给一个动作、一个判断标准、一个损失上限，不给计划和阶段。
6. **陪跑一次只交付一个阶段**，每阶段固定六件东西（目标、动作、交付物、话术、账本、判断点），阶段结束必须复盘三选一。

## 理由

**为什么不用总分**：6 项各 2 分加 1 项 0 分等于 12 分，看起来能过，但那一项若是现金流断点，结论应当是出局。总分会把否决项稀释成可接受的扣分。

**为什么保留最小代价出口**：用户明确要求「判断不该做就没有后续」。完全切断的风险是新手被拒绝后不会停止，而是裸奔入场——投入全部资金、不做任何验证。给一个两周内、损失可控的动作，比什么都不给更能保护他，同时仍然不提供陪跑。

**为什么体检不用市场数据**：七项全部依赖用户自己提供的条件，可解释、可复算、不依赖外部来源，因此不违反「不虚构市场数据」的规则。

## 后果

- `SKILL.md` 主流程由 8 步线性改为两阶段加闸门。
- 新增 `references/intake-questions.md`、`references/checkup-scorecard.md`、`references/coaching-templates.md`。
- `references/output-templates.md` 职责收窄为文档与 PPT 输出。
- 新增样例 06（体检报告与三档判定）、07（陪跑单阶段交付）。
- 验收场景由 5 个扩到 11 个，其中新增场景包含「用户要求跳过体检」。
- 后续若要支持「用户已有完整方案、只需文档交付」，需再补一条不经过闸门的旁路规则，当前未定义。
