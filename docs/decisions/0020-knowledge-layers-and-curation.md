# 0020 知识分层、按需检索与审核式经验沉淀

- 状态：已采纳
- 日期：2026-10-30

## 背景

项目服务多个行业的创业新手，不可能在首次安装时预置完整行业知识。平台规则、地区政策、价格和供应情况还会变化；只靠静态卡片会过期。另一方面，实际执行与复盘能产生可复用经验，但单个案例可能有偏差，不能直接改写通用判断规则。

## 决定

1. **通用核心保持轻量。** 随项目分发通用流程、原型方法、检索协议、证据标准和陪跑结构，不以行业覆盖数量作为目标。
2. **动态事实运行时检索。** 按用户当前方向、地区和阶段查询最新资料，记录来源与日期；静态卡片只给检索起点、结构和判据。
3. **知识按行业、平台或任务成为独立模块。** 仅在内容有复用价值且能说明来源、适用范围和复核日期时固化；缺少资料时按现有规则检索并实测，不为填满目录建卡。
4. **经验采用审核式沉淀。** 运行或复盘中出现的观察先进入候选状态，区分自述、事实、推断和未知；核实来源与边界后由维护者审核，再更新模块或样例并做回归检查。
5. **单个案例不自动成为通用结论。** 不从一个成功或失败案例推导因果、成功率或普遍规则；需保留时间范围、证据等级和适用条件。
6. **陪跑任务逐步交付。** 用户进入某项经营操作时，一次指导一个可执行动作，给前置条件、步骤、交付物、验收点和停止条件；用户完成并反馈后再判断下一步。
7. **本决策不引入用户数据集中收集、服务器、后台任务或自动同步。** 这些系统边界另行讨论和决策。

## 理由

- 轻量核心减少安装体积和过期内容，同时保留跨行业可复用的方法。
- 运行时检索适合变化快的平台规则和当地信息，行业模块适合重复出现、来源稳定的操作结构，两者职责不同。
- 经验审核把真实执行反馈转成可审阅的改进，而不让一次误报污染所有用户的判断。
- 按单个经营任务指导，可以把联网检索转成真实操作步骤，避免只给行业概述或一次输出过长计划。
- 明确“未实现”边界，避免把知识维护方向误写成已经具备的自动学习能力。

## 后果

- `docs/architecture-map.md` 描述知识分层、任务级陪跑和审核发布生命周期；`docs/capability-index.md` 将任务指导与知识维护标为待建设。
- 后续新增行业模块时，要记录复用理由、来源、适用范围和复核日期。
- 后续修改通用规则时，需由维护者审核并补充或更新对应行为样例；静态卡不能替代每次任务的运行时检索。
- 若未来要集中收集案例或自动同步，必须另立决策，说明数据来源、授权、存储与删除边界；本记录不预设实现方式。
