# 0028 检索入口改为「自带能力优先」

日期：2026-11-01。修订 [0015](./0015-search-fallback-in-flat.md) 确立的检索前置判断顺序。

## 问题

0015 与后续文案把检索入口写成「检索前先判『没网』还是『没工具』」。这个顺序隐含了一个假设：**智能体进入检索前需要先花动作确认环境**。但实际宿主分两类：

- 豆包、Codex 这类宿主**自带搜索引擎**，工具列表里检索能力现成可用，任何前置判定都是多余动作；
- 缺工具或缺网络的宿主，环境缺陷会在**第一次真实检索的报错里**暴露出来，不需要提前探测。

先判环境的写法还有两个副作用：一是让自带搜索的宿主误以为必须走兜底端点；二是「判定环境」容易被执行成一句没有动作的自我陈述（「我可能有网」），反而推迟了第一次真实检索。

## 决定

检索的第一动作改为**直接用会话自带的能力查**：自带搜索、抓网页、检索类 MCP，哪个在就用哪个，按检索计划发起第一次真实检索。分支判定后移，全部以第一次检索失败为前提：

| 第一次检索的结果 | 走向 |
| --- | --- |
| 正常返回 | 继续六步循环，不进任何分支 |
| 报凭据错误（缺 API key、401） | `search-fallback.md`，公开端点补检 |
| 基线域名也打不开 | `offline-degradation.md`，先告知再降级 |

0085 之前判据不变：端点候选池仍不排顺序、判定性关键词仍是唯一成功判据、摘要仍不进 H2 分母。本记录只改**入口顺序**，不改兜底协议本体。

## 改动落点

- `references/runtime-loop.md`：第 3 步加「第一动作是直接查」段；「没有联网能力时」一节开头改为「自带能力失败后才进入」。
- `SKILL.md`：第 6 步段落重排为先用自带能力、失败再分「没网/没工具」；「必须遵守」对应条目同步。
- `docs/capability-index.md`：检索工具缺失兜底行的触发条件与判定列同步。
- `examples/24-search-fallback.md`：自检清单第一条按新顺序改写。

## 不改的

- [0015](./0015-search-fallback-in-flat.md)、[0016](./0016-endpoint-pools.md) 的端点池与判定方法原样有效。
- 降级协议（先告知、两条路、不做启动放行）原样有效。
- 旧决策记录按惯例不原地改，以本记录为准。
