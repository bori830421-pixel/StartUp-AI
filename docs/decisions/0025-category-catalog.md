# 0025 品类目录：封顶 11 类，插在门类与原型之间

- 状态：已采纳
- 日期：2026-10-31

## 背景

定位层此前只有两端：国标 20 门类（官方口径，太粗——F 门类下便利店与无货源电商的模式分叉完全相反）与七种原型（收入结构，太抽象——摆摊与网约车同属「卖时间」，必查项毫无交集：一个查摊位合规，一个查网约车双证）。

维护者同时提出两条要求：不得来一个项目建一张卡，要先把普通人能接触的创业方向收进一个封闭的分类目录；药品开发、医院这类普通人不可及的方向要明确排除，而不是留白。

外部检索佐证（2026-10-31，360 搜索与搜狗微信，L4）：公开内容里的「普通人创业」高度聚在餐饮、零售电商、生活服务、技能变现、内容流量、加盟代理、涉农几个族群，与下面的品类划分一致；但划分依据是结构与个体户分布数据（A 级：批零 52.5% + 住餐 21.3% + 居民服务 11.8% = 85.6%，见 `data/industry-taxonomy.md`），不是内容热度。

## 决定

1. 新增品类层：`data/categories/`，**11 个品类封顶**，插在门类定位之后、资金带筛选与原型识别之前。目录是闭集；方向落不进任何品类时，按门类做结构推演（现行规则不变）。
2. 每张品类卡分两部分：**骨架**（国标门类、登记与许可起点、原型候选、典型资金带档位、模式分叉、线上必查项、口语识别词——只含结构，不含数字）与**检索缓存**（真实评估沉淀的 L1–L3 内容，逐条标级别与复核日期）。「行业卡」称呼退役，三张既有卡平移为品类卡的缓存节，内容原样保留。
3. 11 个品类：餐饮食品、零售卖货·线下、电商与线上卖货、居民生活服务、出行与配送、技能接单与专业服务、内容与流量、加盟连锁、教育与文体娱、涉农与食品加工、租赁与中介。加盟是横切品类，与其加盟的对象品类组合加载。
4. 不可及方向（牌照、执业资质、特许经营类）不进目录，在总表列排除清单，每条给「为什么不可及 + 相邻可及品类」。
5. 检索预算公式不变（线上必查项 × 2，上限 12）。品类必查项与原型卡检索清单过渡期取并集，超 7 项按既有规则拆评估。

三条防退化红线：

- 骨架字段不得出现具体金额、客单、成功率；数字只能进缓存节且带级别与日期
- 骨架一次建齐，缓存允许 8 张为空——为填满而编数字正是 0007 要防的退化
- MCP 不加工具：品类是判断辅助，不是确定性计算（0010 / 0014 边界）

## 理由

- 品类是普通人语感与官方体系之间的翻译层：用户说「跑滴滴」「摆摊」，品类卡负责落成必查项与档位，原型卡负责结构与现金流。没有这一层，检索计划只能按原型生成，粒度错位。
- 封闭集合直接回应「来一个项目建一张卡」的问题：来的是项目，落的是品类，品类封顶。
- 排除清单用正面写法（不可及的原因 + 相邻可及路径），延续「不建议启动时给最小代价出口」的思路：新手被拒后不会停止，要给他可走的相邻方向。

## 后果

- `data/industries/` 移除；三张卡的 L1–L3 内容与来源链接原样平移到 `data/categories/`，仅增品类骨架节。引用路径同步：SKILL.md、industry-taxonomy、data/README、archetypes/README、checkup-scorecard、pattern-fork、runtime-loop、架构地图、能力索引、样例 08 / 13 / 15 / 23。
- 第二步待办：`search-playbook` 的查询串挂载点正式移到品类（待一个无缓存品类的行为样例验证后做）；`examples/` 补一个「只有骨架没有缓存」的样例（建议网约车或跑腿）；B 形态只收总表的「品类名 + 一句话边界」，11 张卡不进载荷（依据 0019）。
- 缓存为空的 8 张是设计状态，不是欠账；能力索引的状态口径按「骨架已建、缓存 N 份」表述。
