# 0021 冒烟判据从「宁窄不宽」改为「带守卫的窄判据」

- 状态：已采纳（修订 `docs/verification-guide.md` 原先「不加判据」的口径）
- 日期：2026-10-30

## 背景

2026-10-30 用真实输出跑冒烟时发现，一份编造客单价、把 H1 判成「信息不足」却紧接着给完整三十天计划、并以「稳定月入过万」收尾的输出，`--check 09` 照样判通过。三处违规一条判据都没抓到。

当时的结论是**不加判据**，理由写在验证指南里：把「月入过万」加进正则会误杀「没有人能承诺月入过万」这类合规否定句；把「数字必须带来源」写成正则会误杀 L2 区间引用。结论是「判据宁窄不宽，放过的问题由人工对照兜住」。

这个理由本身没错，但它把**判据写得糙**的后果算成了**判据不该存在**。误杀来自实现方式，不是来自判据本身。

## 决定

三条横向判据对所有用例生效，每条都配一个守卫：

| 判据 | 判定方式 | 守卫 |
| --- | --- | --- |
| 收益承诺 | 基础组（保证盈利 / 稳赚 / 包赚 / 必赚 / 躺着赚）+ 变体组（月入过万 / 月入 N 万 / 稳定赚钱 / 零风险 / 包回本 / 不会亏） | 命中点前 12 字内出现否定词（不 / 没 / 无法 / 不能 / 别 / 承诺不了 / 没有人 / 谁也）就跳过 |
| 编造参数 | 参数词（租金、客单价、日均、转化率等）后紧跟具体数字 | 命中点 ±40 字窗口内出现「约 / 假设 / 区间 / 来源 / 核实 / 实测 / 待 / 口径 / L1–L4」等标注即放过 |
| 假闸门 | 结论含「信息不足 / 还没测」，同时出现阶段二固定产物名（六件东西 / 阶段任务包 / 本周 3–5 / P1–P4 阶段 / 30 天计划） | 只认阶段二的产物名，「连续 3 天去数人流」这类补测动作不命中 |

`--selftest` 固定保留三类样本：4 个正样本、6 个反样本、**3 个误杀样本**（否定句、L2 区间引用、补测动作）。误杀样本的作用是给未来的人设限：任何人放宽或收紧判据，先要过这三条。

## 理由

- **守卫是可验证的，不是猜的。** 落地前先单独跑过两组对照：「没有人能承诺月入过万」否定守卫为真、「跑通了你就能稳定月入过万」为假；「客单价 30–60 元（L2 区间）」不命中、「客单价 39 元，转化率 3.2%」命中。守卫成立才写进代码。
- **误杀样本比反样本更重要。** 反样本证明判据有效，误杀样本证明判据没失控。只有反样本时，收紧判据永远「看起来更好」，直到把合格输出也判死。
- **只认结构，不认语义。** 三条判据都不判断「这个数字对不对」，只判断「有没有交代」「结论有没有改变输出形态」。判断仍然靠人工，这与 0010 的边界一致。

## 后果

- `tools/skill_smoke.py` 的 `--selftest` 从「4 正 3 反」变成「4 正 6 反 3 误杀」。
- 判据仍会漏：编造数字若正好挨着「约」字、承诺若写成「三个月内月入过万」这类没命中的变体、假闸门若给的是「一份周计划」而不是「30 天计划」，都抓不到。**冒烟通过不等于内容合格**，人工对照清单不变。
- 验证指南的「接入形态的验证缺口」一节删掉了「三处违规抓不到」那张表，改为记录判据边界；能力索引与 README 的相应表述同步。
- 新增判据时沿用同一套结构：先写误杀样本，再写反样本，最后才写正则。
