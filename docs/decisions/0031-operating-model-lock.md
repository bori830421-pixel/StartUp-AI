# 决策 0031：经营测算统一口径与人工修改保护

## 背景

2026-11-01，维护者审阅体检交付后指出：预算与剩余现金被偷换，面积、用工和费用未形成必算明细，客单、销量、毛利、净利和现金未贯通。现行 H2 的“固定支出减净利”还会重复扣费用。用户明确要求完善并锁定规则，后续修改必须有人工同意。

## 决定

- 新建 `references/operating-model.md` M01–M09，作为经营测算唯一公式口径；主流程、评分卡、餐饮卡、单文件及 MCP 入口统一接入。通用资金/利润/现金框架适用全部经营形态，门店必须额外列面积、岗位和班次。
- 强制交付六组分析明细：规模用工、开业占款、月度开销、三档收入利润现金、保本线、逐月余额。缺值注明证据状态，不能靠假设判定真实门槛。
- 修正 H2，直接按实际回款与付款算现金；净利润不再次扣固定成本。检查早期累计缺口，不因稳定期现金为正就自动通过。
- 闸门不变：未放行不给阶段任务、执行预算及付款/升级计划。体检分析明细必须展示，不能用闸门为由拒绝算账。
- AGENTS 与运行时规范明确人工审批保护；`docs/rule-lock.json` 记录受保护文件 SHA-256，现有 `skill_check.py` 增加确定性校验，禁止提供自动重封开关。公式不进入代码。
- 17/18 保留历史检索和版式记录，撤销旧财务正确性；35 提供闭合正反例。本次不修改原 PPT 及历史 brief。

## 理由

只补某张 PPT 无法约束后续宿主。规则必须在目录、单文件、MCP 三形态可读，且计算链可复算。审批约束保护含义，指纹门禁发现文件变化，两者不能互相替代。

## 后果与验证边界

新增规则仍为文档流程，不承诺智能体绝不犯错。批准须来自真实维护者指令，清单中的文字只是索引记录，不是可机器证明的身份签名。拥有仓库写权限者技术上仍能修改规则和校验器；这里不是操作系统访问控制。

新增指纹检查属于维护校验，不是经营判断实现。源文件改变时先审人工批准再重封；产物哈希、单文件一致性、MCP 自检、冒烟判据、文档结构继续全部运行。增加负向回归：篡改保护文件、删除清单/保护项、路径越界均须失败，合格基线通过。
