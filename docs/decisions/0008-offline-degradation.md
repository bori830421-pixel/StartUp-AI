# 决策记录 0008：没有联网时的降级规则

- 状态：已采纳
- 日期：2026-10-28

## 背景

0007 把技能定位成运行时流程，第 3 步「执行检索」依赖联网。用户随即指出一个执行层问题：

> 运行时还有一个必须处理的实际问题：如果 AI 运行环境无法联网，该如何降级处理。提示没有网络，需要联网。

初版只写了一句话「把检索计划交给用户」。这不够，有两个漏洞：

1. **没规定要不要告知。** 不告知就等于默默降级，用户分不清哪些是查到的、哪些是卡片里的旧内容。
2. **没规定结论能到哪一档。** 没有这条约束，同一个方向在断网时会给出两种相反的判断——有人判「大概率可以」（推演当通过），有人判「不建议启动」（没查当不通过）。

## 决定

1. **先告知，后降级。** 降级提示放在输出最前面，说清缺的是哪一类信息，给「你开联网 / 你自己查」两条路，A 优先，不给第三个选项。
2. **判定要试探，不凭感觉。** 发起一次最小检索，失败重试一次即判定离线；连续重试属于浪费预算。
3. **区分四种「搜不了」。** 没有工具、工具失败、搜得到但打不开原文（半离线）、搜得到但为空（不是离线，是查不到）。四者输出形态不同，不能混用。
4. **结论封顶在「信息不足」。** 无网络时 H3 合规前置必然挂起，所以不可能放行；同时也不许判「不建议启动」。
5. **用户带回的结果按来源分级。** 官方原文与平台官方页算 L3；窗口口头答复记为「用户口述」，只能把 H3 推进到「待核实」，并给补凭证的出口；朋友转述不算查询。

## 理由

**为什么必须先告知**：这个技能的输出看起来都一样专业，用户无法从文字上分辨哪句查过、哪句是推演。不告知就等于把分辨成本转嫁给最没有分辨能力的人——新手。

**为什么结论封顶在信息不足**：H3 是硬门槛，它依赖政策事实。断网时这项的查询动作没有发生，按既定口径就是「信息不足」。如果允许推演通过，等于把硬门槛变成软约束；如果允许推演不通过，等于用猜测误杀方向。两种都会让闸门失效。

**为什么不能判不建议启动**：`checkup-scorecard.md` 已经定死「没查 ≠ 查了不通过」。断网是最典型的「没查」，判不通过就是拿环境问题惩罚用户的方向。

**为什么只重试一次**：检索有预算（0007）。断网时反复重试不产生新信息，只消耗轮次，还会让用户以为快好了。

**为什么要区分「搜得到但为空」**：这是「这个类目公开信息稀缺」，处理方式是直说查不到并给实测方法；而离线是环境问题，处理方式是让用户换环境。混同会让用户误以为换个网络就能查到，实际换十个网络也查不到。

**为什么用户口述只能到「待核实」**：窗口人员的口头答复没有凭证，换个窗口可能就是另一个说法。给「待核实」并留补凭证的出口，比直接采信安全，也比直接否掉有用。
