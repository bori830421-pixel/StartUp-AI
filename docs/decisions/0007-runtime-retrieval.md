# 决策记录 0007：技能是运行时流程，不是静态知识库

- 状态：已采纳
- 日期：2026-10-30

## 背景

用户指出一个方向性错误：

> 我们这个项目不是脱离网络自问自答，而是要根据行业，在网上快速找出资料，然后整理解答。而且这个是给 AI 的技能，MCP 这类的，而不是脱离现实侃侃而谈。

问题在实现上已经发生了。经过 0003（行业档案）和 0006（原型分类）两轮建设，仓库里已经有一批卡片：七张原型卡、三张行业卡、一份数据分级规则。体检时读卡、按卡给结论——这个流程跑起来很像样，但它有三个结构性缺陷：

1. **会过期。** 政策一年一变，平台规则一季一变，价格随时变。卡片里的数字三个月后就是错的，而且它不会自己报警。
2. **会自问自答。** 只读卡片，输出的是「我以前记下的东西」，不是「现在真实的情况」。用户问的是后者。
3. **覆盖不全。** 卡片永远补不完所有行业。真要覆盖，等于把技能做成一个需要常年维护的数据库。

## 决定

1. **技能的定位是运行时流程，不是静态知识库。** 每次接到方向都跑一遍循环：分型 → 生成检索计划 → 执行检索 → 校验来源 → 判断 → 输出。
2. **卡片只决定搜什么、怎么判，不提供结论。** 原型卡划结构和边界，行业卡降为「已检索结果的缓存」。
3. **`SKILL.md` 插入第 6 步「定向检索」**，位置在模式分叉之后、七维体检之前。原体检、判断、下一步顺延为 7、8、9。
4. **设检索预算：两轮、约 8 个查询。** 超出即停，带空缺出结论。
5. **行业卡设有效期。** 超过六个月只当检索起点，超过十二个月视为无卡。
6. **输出附检索记录表**（查什么 / 查询串 / 结果 / 级别与处理），让过程可复现、可验证。

## 理由

**为什么不是「卡片写得更全一点」**：卡片再全也是快照。问题的性质不是覆盖率，是时效性和来源。把卡片写全，等于用一个更大的静态库掩盖同一个缺陷，维护成本还会指数上升。

**为什么框架仍然必须有**：没有框架的搜索是被 SEO 牵着走。搜「家政创业成本」，前排全是招商加盟平台；搜「摆摊赚钱吗」，出来的是幸存者偏差。框架的作用不是提供答案，是把搜索从「漫游」变成「定点」——只查四到五项，查完就够。

**为什么检索预算这么紧**：用户要的是「快速找出资料」。无限搜索既慢又容易跑偏，而且搜得越多，越容易把无关细节当成专业感。两轮之后必须出结论，三种情况都要停：信息确实稀缺（直说查不到，给实测方法）、问题太宽（收窄再搜）、在无关细节打转（用反证测试砍掉）。

**为什么强调「摘要不等于原文」**：这是 AI 检索最容易出错的地方。摘要会截断「但是」「除外」这类限定，会把旧版本当当前版本，会把自媒体解读和官方原文混在一起。政策条款、处罚标准、办理条件必须打开原文；平台规则必须打开官方帮助页。

**为什么行业卡要设有效期**：缓存不设过期时间，就会变成假依据。设了有效期，卡片的价值就从「提供答案」变成「省一次搜索」，这才是它该有的位置。

## 后果

- 新增 `references/runtime-loop.md`：六步循环、两轮检索预算、摘要与原文的分界、什么算查到了、检索记录表、退出条件、与静态卡的关系。
- 新增 `references/search-playbook.md`：四类查询公式、七个原型各自的查询串模板、站点限定、六类垃圾识别、地区变量处理、差计划与好计划对比。
- `SKILL.md` 新增第 6 步「定向检索」并重排后续步骤编号；`description` 补入「按原型生成检索计划、从网上取当前资料」；必须遵守新增检索预算一条。
- `data/README.md` 明确「行业卡是缓存，不是依据」，并给出六个月与十二个月两条失效线。
- `references/research-protocol.md` 定位收窄为「判断口径」，与流程、查询串两份文件分工。
- 新增样例 15：同一方向，只读卡片与跑检索循环的输出差异。
- 后续新增行业卡时，正确心态是「预置一份检索结果缓存」，不是「补齐知识库」。
