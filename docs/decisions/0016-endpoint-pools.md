# 0016 端点不排顺序：国内 / 境外两份候选池，由智能体现场判断

- 状态：已采纳
- 日期：2026-10-30

## 背景

用户报「一些客户说智能体没有联网搜索权限」，实测发现不是没网，而是三件事叠在一起。2026-10-30 在一台只能访问中国大陆网络的机器上，用抓网页工具逐条探测：

- `www.gov.cn`、`cn.bing.com`、`weixin.sogou.com` 都能打开并拿到真实结果；
- `html.duckduckgo.com`、`duckduckgo.com`、`lite.duckduckgo.com`、`search.brave.com`、`search.yahoo.com` 全部 `fetch failed`；
- `www.bing.com` 302 到 `cn.bing.com`，抓取工具不跟随跨域跳转，第一跳就报错；
- `www.baidu.com/s`、`www.sogou.com/web`、`so.toutiao.com` 返回 200，但正文区没有结果（脚本渲染）；Mojeek 返回 Captcha 页。

而 0015 定下的兜底链是 **DuckDuckGo → Brave → 其它**，并且在 0008 的《离线降级》里把「端点全失败」当成降级条件。后果：两个首选在国内网络全灭，唯一能用的 `cn.bing.com` 又被文档判了死刑（0015 时期记录的「Bing 返回广告」）。用户侧看到的就是「没有联网权限」。

这里有两个结构性缺陷，不是端点选型问题：

1. **顺序写死，等于把一次实测结论推广成所有环境的标准。** 端点的可用性取决于运行环境，同一 URL 在别的机器上可能是 200、Captcha、空壳页或广告。
2. **用「端点全失败」代替「网络不通」做降级判据。** 基线域名能打开，就说明网络通着，失败的是搜索入口。这时宣布「连不上网」是误判，而且会让政策原文类必查项白白降级——它们本来可以直接打开部门站点。

## 决定

1. `references/search-fallback.md` 删除固定顺序与「首选」字样，改为**国内可达组**与**境外组**两份候选池，列出 URL 形态、能用时长什么样、已知坑。**该文件不给排名。**
2. 新增「先测基线再选组」：先打开一个几乎不可能失败的域名，打不开就是真离线；能打开但境外端点连不上，就是国内网络，从国内组开始。**顺序是判断的产物，不是判断的输入。**
3. 失败分为五类并分别记录：连不上、需跳转、空壳页、验证页、广告填充。**五类都算不可用，上表后三类全是 HTTP 200**。唯一可用判据仍是「结果区出现查询主体关键词」。
4. 新增「官方站点直连」一节：政策原文类只要能落到具体部门，就直接打开，不排进端点兜底。这条最稳，不依赖任何搜索引擎的抓取策略。
5. `offline-degradation.md` 第一节的降级判据改为**基线域名**而非端点全失败；提示里的记录从「端点 + 报错」改为「入口 + 失败类型 + 修复线索」。
6. 境外端点**全部保留在候选池**，实测失败写进记录作为环境事实，不据此删除候选——换一条能访问境外的网络它们仍是有效候选。
7. `capability-index.md`、`verification-guide.md`、`references/README.md`、`AGENTS.md` 口述、`SKILL.md` 中所有硬编码「DuckDuckGo → Brave」的表述一并改掉。

## 理由

**为什么不排顺序。** 排序只在「所有环境都一样」时成立，而端点的地域可达性恰恰是最不均等的属性。写死顺序，等于让后一种环境照着念一张不属于它的表——这正是本次故障的形态。

**为什么用基线域名做判据。** 「端点全失败」有多种原因：网络不通、端点被挡、端点要渲染、端点给了验证页。只有「基线也打不开」才能唯一指向网络问题。混用会让用户把「换个端点就能查」误当成「换条网络才能查」。

**为什么五类失败要分开记。** 对用户的修复建议完全不同：连不上是网络或地域问题，需跳转是用法问题，空壳页和验证页是端点策略问题。只写「失败」，用户无法据此做任何事。

**为什么保留境外端点。** 一次失败记录的是那条网络，不是那个端点。删掉它们，会让能访问境外的用户少掉最有效的通道。

## 后果

- `search-fallback.md` 结构重写：候选池、基线判定、失败分类、官方直连、实测记录。原「可照抄代码」一节随固定顺序一并移除——代码示例会诱导模型照抄而不做现场判断。
- `offline-degradation.md` 第一节多一张基线判定表；第五句话术改为「入口 + 失败类型」。
- `examples/24-search-fallback.md` 第二、三、六节重写：先测基线、按基线选组、入口全失败时的落点。
- 新增本节决策记录，`docs/README.md` 决策表补一行。
- **未做的验证**：本次只在一台中国大陆网络的机器上实测。境外组的可用性没有重新验证，记录里保留 2026-10-29 的原始结论并标为「有环境可用」，不作普遍保证。
