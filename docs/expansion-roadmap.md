# 创业陪跑能力推进路线

本文把项目的知识分层方向拆成可执行的文档建设顺序，供维护者或后续智能体接手。目标是让开源、免费、由用户本机 AI 客户端运行的创业指南，逐步从「评估方向」扩展到「陪用户做完一项具体经营任务」。

## 推进边界

- 不预装所有行业的百科资料；每次只处理用户当前的项目、阶段和任务。
- 需要变化的政策、平台规则、价格、供应和市场信号，执行任务时重新检索，并记录来源与日期。
- 用户未通过启动条件闸门时，只给允许的补测或最小代价动作；不得提前输出完整经营计划。
- 不假装登录商家后台、联系供应商或完成上架。智能体提供资料和操作指导，用户执行后反馈真实结果。
- 本路线不包含用户案例集中采集、服务器、后台、自动同步或模型自动训练。

## 单项任务的交付格式

每次指导只推进当前这一项，并给出以下内容：

1. **目标与前置条件**：这一步要验证或完成什么，缺什么输入就先问什么。
2. **当次检索**：当前规则或市场事实查什么、打开哪些原文、来源日期和可靠程度；查不到的内容明确留空。
3. **具体动作**：按用户能在网页、平台或线下完成的顺序写操作；需要登录的数据由用户查看和提供。
4. **交付物**：例如候选商品比较表、供应商询问清单、单品利润测算或上架资料草稿。
5. **检查点与停止条件**：什么结果算继续，什么结果要补查、换方案或停止；不通过时不跳到后续任务。
6. **结果回报**：请用户带回这一步的实际数据或遇到的问题，再决定下一步，不预先铺开整条计划。

## 小红书首个模块的任务顺序

这是一条模块建设顺序，不表示项目已经具备这些平台专属指南，也不代替每次检索：

1. 确认目标人群、使用场景、预算与经营模式；先过启动条件闸门。
2. 形成少量选品假设，使用可查的公开信号筛选；明确哪些结论仍需样品、访谈或小额测试。
3. 找候选供货渠道，核对资质、样品、起订量、交期、售后、发票和平台要求；不把供应商宣传当作独立证据。
4. 用用户确认的进货、运费、平台费用、包装、退货等数字测算单品经济账；缺项就做区间或标空缺。
5. 检索当前官方类目、资质、商品发布和禁售规则，再制作上架资料草稿；不能把旧规则写死在模块里。
6. 用户在自己的账号内完成上架与内容发布，带回页面状态和真实数据；智能体不声称已替用户操作。
7. 按预先设定的小额、短周期指标复盘曝光、点击、咨询、订单、毛利和售后，判断继续、调整或停止。

## 后续智能体接手方式

接手后按此顺序工作：先读根目录 `AGENTS.md`、本文件、`docs/architecture-map.md`、`docs/capability-index.md` 和决策记录 0020；再检查现有 `references/`、`data/` 与 `examples/` 索引，避免重复造内容。从阶段 0 开始，每轮只完成一个阶段；新建目录必须带 `README.md` 并更新上级索引；交付前标明新增能力的成熟度并跑适用的文档检查。用户案例采集、服务器或自动同步不是本路线的实现任务，必须等单独决策。
