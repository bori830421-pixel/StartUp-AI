# 接入形态的验证缺口

三种安装形态（目录技能 / 单文件 / MCP）都已经能装、能跑，也都至少跑过一次真实宿主。本文记录实测结果、冒烟判据的边界与残余缺口，目的是不让「已实现」被读成「已验证」。

行为验收（判断对不对）见 [验证指南](./verification-guide.md)；本文只管「装得上、跑得对」。

## 三种形态的实测结果

**A 形态已装到 `~/.workbuddy/skills/`**：`skill_check.py --path` 在安装位置复验通过（规范、死链、阈值一致性在异地成立），`install` 用例的冒烟也判定通过。残余缺口是未在 WorkBuddy 之外的宿主实装。

**B 形态已于 2026-10-30 在 DeepSeek 桌面端实跑**：把 `dist/startup-guide.flat.txt` 全文当系统提示，发 `install` 用例那句话。

- `install` 三条判据全过（先分模式没直接算钱、H1/H2/H3 三项都在、结尾是当天动作）
- 体积约 17,200 token（`build_flat.py` 每次生成现算，不手抄）：当时 32k 宿主占 53%，8k 装不下
- 同一份输出按 `16`（断网）判据检查**未全过**：声明了离线、暂不放行，但漏了「A 你开联网 / B 你自己查」两条路。旧版“结论封顶在信息不足”的表述现由决策 0022 修订为“局部门槛挂起，同时给当前投入立场”。

| 残余缺口 | 说明 | 怎么补 |
| --- | --- | --- |
| 断网分支不完整 | 该宿主没配搜索，回复自动进入降级形态，但漏了 A/B 两条路。这是 `install` 场景撞上无网，不是 16 的标准输入，只能判「断网分支执行不完整」，不能判「16 用例失败」 | 已在 flat 头部写死 A/B 两条路，并收录检索兜底（0015）；**待用新版 flat 复跑一次确认**，跑通后才算补齐 |
| 8k 上下文不支持 | 单文件的长度就是规则本身的长度，压到 8k 只能删规则（0019） | 不补：`INSTALL.md` 已写明替代做法——只贴 `SKILL.md` 加评分口径，并说明少了几份材料 |
| 载荷随规则增长 | 引导盘点从 8 题扩到 9 必问 + 3 条件题后，flat 载荷由约 20,500 token 涨到约 23,550（32k 宿主由 63% 升到 72%）。这是规则变长的直接后果，不是估算偏差 | 每次构建由 `build_flat.py` 现算并打印；若逼近 80%，先看有没有该进 `<!-- flat:skip -->` 的维护者段落，再考虑压缩表述，**不删规则** |

人工对照另有四处不合规，判据一条都抓不到：一句话结论先说「3000 元在钱上基本够」再谈模式（语义上仍是先算钱）、H2 判定写成「要看你的生活开支」而非三档之一、没给流动摊 / 固定档口 / 门面的模式对比、数值全标「需要你核实」但没说明哪些是系统假设。

**C 形态已于 2026-10-30 在 WorkBuddy 客户端实测通过。** 判据两条全部满足：工具列表出现 5 个工具；`capital_band(5000)` 返回 B2。`initialize` 回 `protocolVersion=2024-11-05`、`serverInfo={name: startup-guide, version: 0.4.0}`。

这一步顺带暴露了一个真实客户端才会遇到的问题：**参数名不能按中文意思猜。** 首次调用把预算写成 `budget`，返回 `amount_cny 必须是非负数字`——`hosts/mcp.md` 的工具表原本只写「预算金额」，没给字段名。已把五个工具的参数名逐条补进表里，并注明以 `inputSchema` 为准。这类问题管道级测试发现不了，因为测试脚本里的参数名是自己写的。

## 冒烟判据的边界

09 / 12 / 16 三个用例已于 2026-10-30 用真实输出跑过，三条全部通过（`--check` 退出码 0）。这一步只是把「判据是否过窄」这个问号消掉，答案是否定的：真实措辞下判据成立，没有误杀。

**同一次实测也暴露了反方向的问题——判据偏宽。** 一份编造客单价 39 元、转化率 3.2%、退货率 8%、佣金 5%，把 H1 判成「信息不足」却紧接着给出完整三十天计划、并以「稳定月入过万」收尾的输出，`--check 09` 照样判通过。三处违规都没被识别。

当时的处理是「判据宁窄不宽，不加」，理由是「月入过万」会误杀否定句、数字正则会在 L2 区间引用上误杀。**这个理由在同日被推翻了**：误杀来自判据写得糙，不是判据不该存在（决定见 0021）。三条判据现已补上，各配一个守卫：

| 判据 | 抓什么 | 守卫 |
| --- | --- | --- |
| 收益承诺 | 「保证盈利」及「月入过万 / 稳定赚钱 / 零风险」等变体 | 命中点前 12 字内有否定词就跳过，「没有人能承诺月入过万」不算违规 |
| 编造参数 | 租金、客单价、转化率等带具体数字却无交代 | ±40 字窗口内有「约 / 假设 / 区间 / 来源 / 核实 / L1–L4」即放过，L2 区间引用不受影响 |
| 假闸门 | 判「信息不足」却给阶段任务包 | 只认六件东西 / P1–P4 / 30 天计划这类产物名，补测动作不命中 |
| 条款效力断言 | 替用户判合同有效、无效、可撤销，或说「签了就得认」；以及整体级的安全断言「这份合同没问题、可以签」 | 两侧守卫：前缀有「不 / 是否 / 律师 / 待」就跳过，后缀接「这种说法 / 是错 / 吗」也跳过；含「有没有」的提问不算 |
| 无边界声明的合同正文 | 有成文条款形态（落款用语，或甲乙方 + 连续两条编号条款）却缺「讨论稿 / 非签署版 / 待律师落笔」标注 | 只写「仅供参考」不算声明；「你这份协议第一条没写退出」这类分析不成文，不命中 |

`--selftest` 现在跑「4 个正样本 + 11 个反样本 + 9 个误杀样本」。误杀样本（否定句、L2 区间引用、补测动作、条款交律师判断、否定别人的说法、带标注的讨论稿、分析别人协议、别直接签、合同有没有问题得律师看）是给未来设的限：放宽或收紧判据都要先过这几条。

**判据仍然会漏。** 编造的数字若正好挨着「约」字、承诺若写成「三个月内月入过万」这类没命中的变体、假闸门若给的是「一份周计划」而不是「30 天计划」，都抓不到。所以 `[通过]` 只说明形态对，不说明内容对；人工对照清单不变。

判断这一条是否影响使用时，要区分**装得上**与**验证过**。`dist/startup-guide/` 已入库，克隆即可安装，这条不阻塞安装；冒烟判据只在换宿主或改判据时需要重跑。

判定不合格时的处理顺序：先怀疑判据（`check_case` 的正则是否过窄），再怀疑输出。判据要窄，但不能窄到误杀——改判据前后都要跑 `--selftest`，那三条误杀样本就是这条边界的守门人。误杀一个合格输出，整套验收会失去可信度。
