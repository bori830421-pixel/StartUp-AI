# 架构地图

## 当前状态

项目处于规则与文档框架阶段，已有 16 个行为样例（`examples/`）。当前没有实现代码、数据存储、外部集成或自动化任务；下列模块是技能的逻辑边界，不代表已有独立程序。

## 产品目的与使用者

本技能服务于创业新手，尤其是预算有限、方向尚不明确，或不知道自己该从哪一步开始的个人。

主流程是两阶段串行，中间有闸门：

```text
用户输入
  → 引导盘点 → 目的分离 → 待评估方向
  → 识别原型：落到七种生意结构之一
  → 模式分叉：先确定用哪套成本结构算分
  → 定向检索：按原型生成检索计划，两轮约 8 个查询
  → 七维体检：H1–H3 硬门槛、S1–S4 软约束
  → 闸门
      ├─ 放行 ────────→ 分阶段陪跑 P1→P2→P3→P4 → 阶段复盘
      ├─ 有条件放行 ──→ 补短板 → 复核 → 通过才进 P1
      ├─ 信息不足 ────→ 补测动作 → 回到对应门槛重判
      └─ 不建议启动 ──→ 最小代价出口 → 结束
```

闸门是这套架构的核心。它不是流程中的一个可选步骤，而是决定后续是否发生的判定点：没有通过体检，不产生阶段任务、预算表和行动计划。

闸门有四种去向，不是两种。只画「通过 / 不通过」会把「有条件放行」和「信息不足」压掉，而这两种恰恰是最常见的输入形态。

模式分叉位置在体检之前。同一类目下不同经营模式的成本结构完全不同，不分模式直接算钱，分数算得再细前提也是错的。规则见 `references/pattern-fork.md`。

定向检索位置在模式分叉之后、体检之前：结构来自原型，当前事实来自检索，参数来自用户实测。三者不能混用——用卡片回答事实问题，技能就退化成一个会过期的知识库。规则见 `references/runtime-loop.md` 与 `references/search-playbook.md`。

## 能力模块

| 模块 | 负责内容 | 主要输出 |
| --- | --- | --- |
| 引导盘点 | 用 8 道选择题收集目标、地区、能力、时间、资金和承受能力 | 盘点结果表 |
| 目的分离 | 区分用户要的是现金流、时间自由、做成自己的事还是学一门生意 | 评估口径说明 |
| 方向探索 | 从兴趣、技能或关键词提出可比较的创业假设 | 候选方向及适配理由 |
| 原型识别 | 把方向落到七种生意结构之一，识别叠加原型 | 原型定位与结构推演 |
| 模式分叉 | 同一类目下先确定用哪套经营模式的成本结构算分，默认取最轻的模式 | 模式结构对比与重算后的分项 |
| 运行时检索 | 按原型生成检索计划并执行，两轮约 8 个查询内收口，校验来源后分级 | 检索计划、检索记录表 |
| 离线降级 | 检索跑不起来时先告知再降级：判定四类「搜不了」，给两条路，结论封顶在信息不足 | 降级提示、检索清单、带空缺的判断 |
| 启动条件体检 | 三个硬门槛加四个软约束，用用户信息、原型结构与检索到的当前事实 | 体检报告与分项依据 |
| 信息不足处理 | 区分「没测过」与「测了不够」，把未测项挂起，其余维度照常算 | 补测动作与分岔结论 |
| 行业档案引用 | 把档案卡当检索缓存，按数据级别与复核日期决定能否进入判断 | 结构依据与实测清单 |
| 闸门判定 | 输出放行、有条件放行、信息不足或不建议启动 | 一句判断与短板清单 |
| 下一步唯一动作 | 不管结论落在哪一档，每轮输出以一个当天能开始、做完能做决定的动作结尾 | 单个动作与判断标准 |
| 分阶段陪跑 | 一次交付一个阶段：目标、动作、交付物、话术、账本、判断点 | 阶段任务包 |
| 阶段复盘 | 三选一并区分执行、假设、方向三类原因 | 复盘记录 |
| 交付整理 | 将经用户审阅的方案组织为报告、演示文稿或 PDF 内容 | 文档大纲、页面文案或文件 |

## 数据与集成边界

- 用户输入是个性化建议的主要依据；未获用户提供或未核实的信息应标成假设或待验证。
- 本阶段不定义持久化用户数据，不收集不必要的个人或商业敏感信息。
- 市场、法规、价格、平台政策等动态事实需要按任务使用可用的联网来源核实，并记录来源与访问日期。
- 检索有预算：两轮约 8 个查询。两轮后无论是否查全都出结论，空缺项标为空缺并转成用户的实测动作。
- 联网能力是外部依赖，不保证可用。不可用时先告知再降级：结论封顶在「信息不足」，不允许把卡片内容当作检索结果。规则见 `references/offline-degradation.md`。
- 静态卡片（`data/archetypes/`、`data/industries/`）只决定搜什么、怎么判，不提供结论。行业卡是检索缓存，超过六个月只当检索起点，超过十二个月视为无卡。
- PPT/PDF 文件生成依赖会话中的文档工具；工具不可用时，提供结构完整、可复制的内容。
- 当前不包含后台任务、自动监控、外部账号写入或自动发布。

## 入口与文件边界

- `SKILL.md` 是 AI 使用入口，保持为流程与规则索引。
- `README.md` 是对外说明，供第一次接触本项目的人快速了解范围与用法。
- `AGENTS.md` 是项目协作与维护规则。
- `docs/` 保存架构、能力与验证说明及决策记录。
- `references/` 保存可复用的提问、评分与陪跑模板。
- `examples/` 保存行为样例，每个样例对应 `docs/verification-guide.md` 中的一个验收场景，用于证明规则可执行。
- `data/` 保存数据分级规则与检索缓存。原型卡按生意结构组织，决定搜什么、怎么判；行业卡是已检索结果的缓存，每张标注数据级别、来源与复核日期，过期只当检索起点。
- 每个目录有 `README.md` 作为二级索引，列出本目录职责、文件清单与新增约定；`AGENTS.md` 的入口只列到目录一级，不逐条罗列文件。
- 文件规模按 `AGENTS.md` 的「文件规模与导航约束」控制：Markdown 建议上限 200 行 / 16 KB，硬上限 300 行 / 24 KB，超过 120 行的文件在顶部加「本文导航」。超限先拆再交付，不把新内容追加进大文件。
- 若后续实现加入代码或外部集成，先补充数据边界、接口责任和验证办法，再扩展实现。
