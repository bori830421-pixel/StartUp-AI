# 模块审核与复核清单

本清单供维护者在新增、修订、拆分或删除行业、平台、任务模块前手工复核。目标是让有复用价值且有依据的内容进入项目，同时把单个案例、过期事实和未验证推断留在候选范围内。

本清单不建立用户案例集中收集、服务器、自动同步或模型自动更新流程。模块进入运行文档前必须由维护者审核。

## 何时使用

- 新建或大幅修订 `references/` 中的任务指南、`data/` 中的品类缓存，或其他可复用经营模块。
- 拟将用户反馈、任务复盘或样例中的观察提升为通用流程、判断规则或行业结论。
- 复核动态信息、来源失效、规则更新或出现失败样例后，决定保留、修订、拆分、删除或暂缓。

一般对话中的即时判断仍按运行时检索规则处理；不必为了单次咨询创建模块。

## 复核步骤

### 1. 说明复用理由与适用范围

- 写清模块解决的重复问题、服务对象、任务阶段及经营模式。
- 列出地区、平台、店铺类型、商品类别、预算和能力等会改变结论的边界。
- 若复用理由只是“目录缺这一类”或“想覆盖更多行业”，不新增模块；按需检索并把事实留在当次任务。

### 2. 拆分证据类型

逐项标注内容属于哪一种：

| 类型 | 记录方式 | 能否直接改成规则 |
| --- | --- | --- |
| 用户报告 | 只记完成任务所需的匿名事实；说明是用户自述，不推定普遍性 | 不能。先核实适用范围与其他证据 |
| 可核实事实 | 附一手来源、页面标题、访问日期和口径；按 `../data/source-grading.md` 标级 | 仅在来源等级、时效和范围都满足时考虑 |
| 推断 | 写明推理链、前提和可能的反例 | 不能单独作为确定结论 |
| 未知 / 待核实 | 指明缺口、影响和下一步核验动作 | 不填估值，不进入判断依据 |

L4 内容只能作为待核实线索；供应商、品牌方、招商和培训机构等利益相关来源要标出利益关系并寻找反证。不得把一次成功、失败、访谈或搜索结果写成普遍需求、利润、转化率或成功概率。

### 3. 核验来源与日期

- 政策、许可、处罚、办理条件和平台规则必须打开当前官方原文；搜索摘要只用于发现线索。
- 参数区间记录地区、对象、采集日期和统计口径。关键判断所需数据不够时，继续保持待核实或转成用户实测动作。
- 来源打不开、页面显示失效、版本不清或彼此冲突时，不用转载页补位；把内容改成运行时检索要求或暂缓发布。
- 遵守 `../data/source-grading.md` 的复核期限；品类缓存另遵守 `../AGENTS.md` 的规则：超过六个月只作检索起点，超过十二个月视为无缓存。

### 4. 检查边界、风险和停止条件

- 模块是否说明哪些情况适用、哪些情况要转人工核验或专业人士？
- 是否把账号、后台、供应商联系和线下执行留给用户，避免声称助手已完成？
- 是否有缺少数据时的处理方式、停止条件和用户回报字段？
- 是否保留启动闸门：未放行时只给允许的补测或最小代价动作，不输出后续完整任务包？
- 是否一次只指导一个任务，并把下一步挂在本次实际结果上？

任一安全、合规、现金流或闸门边界不清，先修订或暂缓；不能靠免责声明保留一条本身无依据的规则。

### 5. 用失败情形和样例回归

- 列出模块最可能误导用户的失败情形、反例和证据不足时的退路。
- 找到所有受影响的行为样例，按现行规则重跑其自检；样例与规则对不上时，修正其中一侧并记录理由。
- 新增或改变判断规则时，补充覆盖正例、反例和信息不足边界的样例；不能只测理想路径。
- 模拟样例只证明输出结构可执行，不证明真实市场规律或真实用户任务已验证。

### 6. 作出审核决定并留下记录

| 决定 | 使用条件 | 后续动作 |
| --- | --- | --- |
| 保留 | 复用理由清楚，来源、范围、风险和样例回归都能支持当前写法 | 更新复核日期与能力状态 |
| 修订 | 核心有用，但来源、边界、表述或停止条件需改 | 修订后重新检查受影响样例 |
| 拆分 | 同一文件混入不同任务、地区、经营模式或生命周期 | 按主题拆分并更新上级索引 |
| 删除 | 无复用价值、来源失效且无法重建，或持续导致错误判断 | 删除文件及所有索引引用 |
| 暂缓 | 关键原文不可读、适用范围未知或证据不足 | 保留为候选，不进入安装内容和通用判断规则 |

没有填写审核结论的候选材料，不进入 `SKILL.md`、常用参考模板或默认检索流程。
