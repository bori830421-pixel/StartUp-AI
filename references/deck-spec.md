## 1. 两类演示文稿，不要混用

| 类型 | 回答的问题 | 页序 | 样例 |
| --- | --- | --- | --- |
| 方案类 | 「这个想法值不值得投」 | 8 页：问题 → 客户与场景 → 方案 → 市场口径 → 商业模式 → 进展与验证 → 团队与资金 | `examples/05-deck-request.md` |
| 测算类 | 「这笔钱该不该动」 | 11 页：见第 3 节 | `examples/18-deck-brief.md` |

判断依据是**受众**，不是页数。投资人要听增长故事，准备投钱的本人要听风险边界。同一个方向，两种讲法结论可以相反。

## 2. 三条内容硬约束

1. **标题必须是结论句。** 不写「项目概述」「成本分析」，写「60 万刚好把店开起来，只剩 2.2 万周转」。读者只看标题也能拿到结论。
2. **每页只准一个主数字。** 一页三个大数字，读者一个都记不住。其余数字降为表格或注释。
3. **每个数字带级别与日期。** 按 `data/source-grading.md` 标 A–E；区间值写清口径。未核实的写成假设，并写明核实方法。

## 3. 测算类：页序与每页必须成立的判断

「必须成立」这一列是硬门槛：**做不到就删掉这一页，不要用形容词填满它。**

| 页 | 页型 | 这页必须成立什么 | 做不到怎么办 |
| --- | --- | --- | --- |
| 01 封面 | `cover` | 标题里有一个可验证的数字结论，且与末页一致 | 没结论说明体检还没跑完，别做 PPT |
| 02 执行摘要 | `three-col` | 三栏各一个数，且三个数不重复 | 三个数凑不齐 → 退回补测，不做摘要 |
| 03 输入条件 | `table-assumptions` | 「已知」与「必须实测」分开列 | 全是待实测 → 说明还没到做 PPT 的时候 |
| 04 钱怎么花 | `table-card` | 总投入区间 + 剩余缓冲，两项都要算出来 | 算不出总额 → 说明必查项没查全 |
| 05 保本线 | `bignum-costlist` | 月固定成本五项齐全（房租/人工/水电/管理/损耗） | 缺项就标「缺项」，不许默认 0 |
| 06 情形对比 | `table-bar` | 三档都能算出净利，净利 = 营业额 × 毛利率 − 固定成本 | 净利算不出 → 成本没闭合，回第 5 页 |
| 07 变量对照 | `two-panel` | 只换一个变量，其余全部保持不变 | 换了两个变量 → 读者无法归因，重做 |
| 08 体检 | `table-footnote` | 每项有判定词（通过/待核实/信息不足），不是只有分数 | 只有分数 → 违反「判断必须挂在分项上」 |
| 09 风险 | `cards` | 每条风险都有「你能做的」，且是动作不是态度 | 写不出动作 → 这条不是风险，是抱怨，删掉 |
| 10 动作 | `timeline` | 每个动作当天能开始，且有一个可量化的判断标准 | 判断标准是「感觉不错」→ 重写 |
| 11 收尾 | `closing` | 一句话能脱离全篇独立成立 | 做不到 → 说明前面没得出结论 |

页数不是死的：测算类可以砍到 7 页（去掉 07、09、10 之一），但不许**加**到 15 页。超过 12 页说明该拆成两次评估。

## 4. 页型选择表

页型定义在 `tools/deck_layouts.py`，几何写死，内容全来自 brief。

| 页型 | 用在哪 | 关键字段 |
| --- | --- | --- |
| `cover` | 封面 | `title_lines`、`meta`、`conclusion` |
| `three-col` | 三栏结论（现状/冲突/解法） | `cols[].tag/label/body/num/unit` |
| `table-assumptions` | 表格 + 右侧假设 + 底部两栏对照 | `table`、`assumptions`、`blocks` |
| `table-card` | 表格 + 右侧深色大数字卡 | `table`、`card` |
| `bignum-costlist` | 主数字 + 成本明细 + 右侧说明 | `value`、`costs`、`total`、`panel` |
| `table-bar` | 表格 + 横向条形对比 + 洞察 | `table`、`bar`、`panel` |
| `two-panel` | 左右对照 + VS | `panels`、`takeaway` |
| `table-footnote` | 表格 + 底部规则说明 | `table`、`note` |
| `cards` | 3–4 张并列卡片 | `cards[].num/title/body/act` |
| `timeline` | 步骤时间线 + 判断标准条 | `steps`、`judge` |
| `closing` | 深色收尾 | `statement`、`supports` |

`panel.items` 的最后一条会被渲染成强调色 —— 用它放这页的落点句。

## 5. brief 怎么写

brief 是一份 JSON，结构为 `{"meta": {...}, "slides": [{"type": "...", ...}]}`。完整可运行样例：`tools/briefs/01-chenghai-zhaoyiming.json`。

写法要点：

- **先写标题句，再写内容。** 标题句写不出来，说明这页的判断还没成形。
- **表格单元格可以是字符串，也可以是 `{"t": "沉没", "c": "red"}`。** 颜色只标异常项（沉没、不确定、负值），不要整表上色。
- **`source` 每条都要写。** 没有来源的页，宁可删页。
- 颜色名用 `tools/deck_kit.py` 的 `PALETTE` 键（`navy`/`red`/`green`/`orange`/`gray`/`dgray`/`cyan`/`lblue`/`lgray`/`xlgray`/`white`/`navy2`）。

## 6. 渲染三级降级

与 `offline-degradation.md` 同构：**先告知，后降级**，不许默默降级成纯文字。

| 级别 | 触发条件 | 交付物 |
| --- | --- | --- |
| L1 出文件 | `tools/deck_engine.py` 可运行且装了 python-pptx | `.pptx` + 逐页 PNG 预览 |
| L2 可粘贴文案 | 无 Python 或无 python-pptx | 按页序输出 Markdown，每页含标题句、要点、数字、Source，用户粘进演示工具 |
| L3 只给页序 | 连排版都不做 | 11 行页序表 + 每页结论句，说明「需要你在演示工具里排版」 |

判断方法：先试跑 `python tools/deck_engine.py --help`；报缺依赖即降到 L2，并把安装命令给用户（`pip install python-pptx -i https://mirrors.aliyun.com/pypi/simple/`）。

降级提示放在输出最前面，一句话说清缺什么：

> 本次未生成 PPT 文件（环境缺 python-pptx）。下面是可直接粘贴的 11 页文案；需要文件的话，装完 `python-pptx` 我再跑一遍。

## 7. 交付前自检

引擎自带三项确定性检查，跑完会打印：

- `[必改]` 文字被后画的色块盖住、文字框互相压住 —— 必须修，改完重跑
- `[提示]` 框留得太紧 —— 目视确认，多半是单行文字撑满

引擎通过**不等于**好看。还要过四道人工关：

| 检查 | 判据 |
| --- | --- |
| 标题句 | 遮住正文，只看标题能否读出结论 |
| 数字一致性 | 封面、摘要、正文、收尾的同一个数是否一致 |
| 假设标注 | 未核实的数字有没有标「假设」与核实方法 |
| 来源 | 每页 Source 有没有级别与日期 |

## 8. 禁止做法

- 引擎报 `[必改]` 仍然交付。
- 把估算值写成确定值，或把区间写成单点。
- 一页塞三个主数字。
- 标题写「项目概述」「市场分析」这类零信息量的词。
- 用形容词填满算不出数的页（「前景广阔」「需求旺盛」）。
- 为了让页数凑到 11 页而拆分或注水。
