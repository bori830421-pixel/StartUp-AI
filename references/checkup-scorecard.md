# 启动条件体检：七维评分口径

三个硬门槛加四个软约束。全部用用户提供的信息计算，不引用市场数据，不做成功率预测。

## 为什么不用总分

6 项各 2 分加 1 项 0 分等于 12 分，看起来能过，但那一项若是现金流断点，结论应当是出局。总分会把否决项稀释成可接受的扣分。所以硬门槛单独判，软约束只排序不求和。

## 硬门槛

### H1 客户可达

问：你能说出 10 个具体目标客户吗（名字、店铺、群、公司）？

| 判定 | 条件 |
| --- | --- |
| 通过 | 能列出 10 个及以上具体对象，不是「理论上存在」的泛指 |
| 不通过 | 列不出，或只能说行业而非具体对象 |

不通过时，结论不是「这个方向不行」，而是「还没到评估阶段」。先做一次客户名单采集，两周内凑够 10 个再回来。

### H2 现金流断点

问：钱能撑几个月？预计几个月有第一笔收入？

先按「首笔收入什么时候来」分成两种情形，用错情形会直接误判。

**情形 A：先投入、后收钱**（卖时间、轻库存、卖技能、卖内容、生产制造）

| 判定 | 条件 |
| --- | --- |
| 通过 | 可撑月数 ≥ 预计首笔收入月数 + 1 |
| 不通过 | 可撑月数 < 预计首笔收入月数 + 1 |

计算口径：

- 可撑月数 = 可用资金 ÷ 月度固定支出（含生活开支，不只是项目支出）
- 预计首笔收入月数取保守值，不取乐观值
- 加 1 个月是缓冲，防止刚好卡在断点上

**情形 B：开业即有收入，但净现金流为负**（买系统·加盟、重库存、堂食餐饮）

加盟店开业当天就收钱，用情形 A 会判「通过」——但真实断点不是「没有收入」，是「每月净流出，撑不到累计转正」。所以改判：

| 判定 | 条件 |
| --- | --- |
| 通过 | 流动资金 ÷ 月净流出 ≥ 爬坡期 + 1 |
| 不通过 | 流动资金 ÷ 月净流出 < 爬坡期 + 1 |
| 信息不足 | 爬坡期与月净流出都没测过 |

计算口径：

- 流动资金 = 可用资金 − 开店投入（加盟费、装修、设备、首批货、押金、转让费）
- 月净流出 = 月度固定支出 − 月净利（净利取行业区间下限，不取招商话术）
- 爬坡期未知时取 **6 个月**，不取 3 个月
- 月净流出为负（净利大于支出）时，情形 B 直接通过

判断走哪个情形，只看一件事：**首笔收入是不是在第一个月内。** 是则情形 B，否则情形 A。

新手最常见的两个错误：把「项目能撑多久」和「我能撑多久」混为一谈（生活开支必须计入）；把「开业有流水」当成「现金流没问题」（流水不等于净利）。

### H3 合规前置

问：这个方向需要前置许可或资质吗？周期多长？

| 判定 | 条件 |
| --- | --- |
| 通过 | 无需前置许可，或许可周期 ≤ 你的准备期 |
| 不通过 | 需要前置许可且周期 > 准备期 |
| 待核实 | 已查过官方渠道，但口径不明、各地不同，或需现场确认才能定论 |

待核实不等于通过。按不通过处理，并写明要查什么、去哪查、问哪一句。

「还没查」不属于待核实，属于信息不足，按后文「第三种状态：信息不足」处理，不判结论。两者的分界见该节的对照表——这是 H3 最容易出错的地方。

## 软约束（0–3 分）

### S1 资金匹配

| 分 | 条件 |
| --- | --- |
| 3 | 可用资金 ≥ 最低启动现金 × 1.2 |
| 2 | 可用资金 ≥ 最低启动现金 |
| 1 | 缺口在 50% 以内 |
| 0 | 缺口超过 50% |

最低启动现金只算不做这件事就收不回的钱：设备、押金、首批进货、许可费用。不算自己的时间。

**这一项必须按模式算。** 同一类目不同模式的「最低启动现金」可能相差数倍，见 `pattern-fork.md`。例：电商无货源代发不含备货，最低启动现金接近零；自备货模式则包含全部货款。用错模式算这一项，会直接把可做的方向判成不可做。

### S2 时间匹配

| 分 | 条件 |
| --- | --- |
| 3 | 每周所需工时 ≤ 可投入工时 |
| 2 | 所需 ≤ 可投入 × 1.5 |
| 1 | 所需 ≤ 可投入 × 2 |
| 0 | 所需 > 可投入 × 2 |

新手普遍低估 2–3 倍。估算时按「熟练后」的工时再乘 1.5。

### S3 能力缺口

| 分 | 条件 |
| --- | --- |
| 3 | 关键动作全会，或缺口 1 个且可外包 |
| 2 | 缺口 2 个，其中一个可外包 |
| 1 | 缺口 2–3 个，且都难外包 |
| 0 | 缺口 3 个以上 |

关键动作指不做就交付不了的动作，通常 4–6 个。先列出来，再逐项标记会或不会。

### S4 失败可逆性

| 分 | 条件 |
| --- | --- |
| 3 | 投入基本可回收（设备可转卖、押金可退） |
| 2 | 可回收一半以上 |
| 1 | 可回收少量 |
| 0 | 基本无法回收 |

这一项决定用户敢不敢真去试。分低不代表不能做，代表先别投钱。

## 判定规则

| 结果 | 条件 |
| --- | --- |
| 放行 | H1、H2、H3 全通过，且 S1–S4 中最多 1 项 ≤1 分 |
| 有条件放行 | H1、H2、H3 全通过，且 S1–S4 中有 2 项及以上 ≤1 分 |
| 不建议启动 | H1、H2、H3 任一项不通过 |

## 第三种状态：信息不足

硬门槛只有通过和不通过两档，但实际会遇到第三种情况：**用户没测过，不是测了不够**。

三种「拿不到答案」的情形必须分开，处理方式完全不同：

| 情形 | 例子 | 判定 | 为什么 |
| --- | --- | --- | --- |
| 已能判断为不足 | 说不出 10 个客户 | 不通过 | 手上确实没有客户，答案已经知道 |
| 信息不足 | 还没去数过客流 | 不判，给补测动作 | 客观上能测，只是没测 |
| 待核实 | 查了，但各区口径不同 | 按不通过处理 | 已尽力，无法在体检阶段定论 |

分界只有一条：**查询动作有没有发生**。

- 没查 → 信息不足
- 查了但查不清 → 待核实
- 不用查就知道不够 → 不通过

「问过同行」「听朋友说」不构成查询，仍算信息不足。查询指查官方渠道或问主管部门。这条分界对 H3 合规前置尤其重要，因为它同时存在「待核实」和「信息不足」两种未定状态。

信息不足时的处理：

1. 不给判断结论，也不给阶段任务
2. 只给补测动作：做什么、做几天、记录什么、怎么判
3. 说明补测后可能出现的两种结果，以及各自对应什么结论
4. 其余可以算的维度照常算，避免整份体检作废

把信息不足当成不通过，会让有希望的方向被误杀；把信息不足当成通过，会让体检变成走过场。这两种错误都很常见。

## 输出格式

```text
判断：<一句结论，必须点出卡在哪一项>
硬门槛：H1 通过 / H2 不通过 / H3 待核实
软约束：S1 2 分、S2 1 分、S3 3 分、S4 2 分
最弱项：<维度> —— <依据>
先补什么：<1–2 个动作>
```

## 三档判断的措辞

- 放行：「当前条件下可以启动。三个硬门槛都过了，最弱的一项是时间，按某个方式压缩就能做。」
- 有条件放行：「先别启动。硬门槛都过了，但能力和资金两项偏弱，先补这两项，补完再复核一次。」
- 不建议启动：「当前条件下不建议启动，卡在现金流：你能撑 2 个月，但预计 4 个月才有第一笔收入，中间 2 个月没有来源。」

## 三条纪律

1. 每项分数必须写出依据，没有依据的分数不写。
2. 不把分数换算成百分比或成功率。
3. 用户不接受结论时，不改分数，改依据——让他提供新信息，重新算。
