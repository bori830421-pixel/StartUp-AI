# 定向检索协议

> 本文件是检索的**判断口径**：哪一层信息能用哪种方式取得、取得后能不能进判断。流程与预算见 `runtime-loop.md`，具体查询串见 `search-playbook.md`。

## 为什么单靠搜索会片面

AI 能搜全网，但搜出来的答案经常片面。原因不在搜索量，在四个结构性问题：

1. **搜索结果是商业内容的产物。** 排在前面的往往是最会做 SEO 的，不是最准确的。搜「家政创业成本」，前排几乎全是招商加盟平台。
2. **没有框架就没有边界。** 不知道该搜什么，就会搜到别人想让你看到的。信息越多，越容易被牵着走。
3. **幸存者偏差。** 能搜到的成功案例远多于失败案例，因为失败的人不写文章。
4. **动态信息会过期。** 价格、政策、平台规则一年一变，旧文章不会自己下架。

所以解法不是「搜更多」，是**先有框架，再定向搜**。

## 框架先于搜索

原型卡就是框架。它告诉你要查什么、不用查什么：

| 层级 | 内容 | 要不要搜 |
| --- | --- | --- |
| 结构级 | 成本结构、现金流节奏、天花板、常见死法、劝退条件 | **不搜**。原型卡已经给出，且这类知识稳定 |
| 参数级 | 客单价、租金、单价、单量、毛利 | 先搜范围做低、中、高场景；只有会改变判断的关键数再现场实测 |
| 事实级 | 法规条款、证照要求、平台规则、处罚标准 | **必须搜官方原文**，且必须提示用户现场核实 |

一句总结：**结构靠推演，参数先检索估算、关键项再实测，事实靠官方原文。**

三层混用是片面的根源——用搜索结果去讲结构（会被广告带偏），用推演去填参数（会编数字），用二手解读代替法规（会错）。

## 三级检索清单

### 结构级：不搜

原型卡已覆盖。如果发现某个方向的结构明显偏离原型，说明原型识别错了，回去重识别，而不是去搜「这个行业怎么样」。

### 参数级：搜、算、再核

先查同城或相近地区的范围、日期和口径；对租金、客单、用工、周转或毛利等关键参数，至少列出低、中、高输入并显示结果如何变化。搜索摘要只能发现线索，优先打开原始统计、招聘或挂牌页面。

只有一个来源时按 L4 线索处理：只能说明「如果该值成立，结果如何」作为压力测试，明确排除在判断依据之外；不能写成市场事实、填成唯一输入或据此通过/否定硬门槛。来源之间不具可比性时分开列情景，不取平均。

结果对参数不敏感时，不把用户送去做无关测量。结果跨过通过线时，给一个最便宜、能替换关键参数的现场核验方式；合同价、实际订单、配方成本和设备报价仍须用本店数据替换。

### 事实级：只认官方原文

政策、法规、证照、处罚，一律回溯到政府网站或法规原文。不引用二手解读、不引用百科、不引用问答。

查到之后必须做两件事：

1. 给链接与访问日期
2. 提示地方差异，要求用户向当地部门确认

## 每个原型的固定检索项

原型卡末尾都有「定向检索清单」，四到五项，查完就够。这是防止「越搜越乱」的关键。

| 原型 | 必查项 |
| --- | --- |
| 卖时间 | 从业资格、车辆准入、营运险、平台抽成 |
| 卖货轻库存 | 点位是否允许、摊位备案、品类季节性、同类摊位销量 |
| 卖货重库存 | 租金与租约条款、周转速度、前置许可、商圈空置率 |
| 卖技能 | 当地市场价、资质要求、用工责任、平台规则 |
| 卖内容 | 平台变现门槛、广告报价、品类限制、对标账号数据 |
| 买系统 | 备案查询、信息披露文件、非本地加盟店流水、合同条款 |
| 生产制造 | 生产许可、环评、消防、同行产能利用率 |

## 判断「搜够了没有」

判据只有一个：**反证测试**。

问自己一句：如果这个数字错了一倍，结论会不会反转？

- 不会反转 → 这个数字不重要，不用再搜
- 会反转 → 这个数字是关键变量，必须让用户实测，或给出两种情形下的结论

例：卖货类目里，「客单价 20 还是 40」会直接改变保本线，属于关键变量。先检索可比范围并按两端计算；结果会改变判断时，再用目标点位或真实订单核验。「包装耗材 0.5 元还是 0.8 元」不会改变结论，不用搜。

这条判据能省掉 80% 的无效检索，也能避免在无关细节上显得很专业、在关键变量上却是猜的。

## 交叉验证规则

| 情况 | 处理 |
| --- | --- |
| 两个独立来源一致 | 可作 L2 使用，标日期与口径 |
| 只有一个来源 | 降级为 L4，只当线索 |
| 两个来源冲突 | 不取平均。标注冲突，说明口径差异，让用户按当地核实 |
| 来源是招商、加盟、培训、代运营 | 归 D 类，必须打折，优先找反证 |

## 识别「看起来像知识其实是广告」

六个信号，见到任一就要警惕：

1. 标题带「揭秘」「内幕」「月入过万」「7 天起店」
2. 正文没有数据来源，只有结论
3. 结尾引导加微信、领资料、报名
4. 域名或账号主体是加盟、招商、培训、代运营机构
5. 全文只讲成功案例，不提失败
6. 给出的数字精确到小数点，但没有样本量

这类内容可以作为「用户可能遇到的说法」记录下来，但不能进判断依据。

## 什么时候该说「查不到」

三种情况必须直说，不许用推演填空：

1. **该类目没有 A 类来源。** 例：家政行业的成本结构，公开数据几乎全是招商平台口径。此时只能给结构判断，明说「没有可靠数据」。
2. **地区差异过大。** 例：小餐饮备案标准各地不同，不能套用别的省市。
3. **平台规则查不到当前版本。** 平台规则会改，旧文章不可信。要求用户自己在平台官方规则页确认。

说「查不到」不是能力不足，是这套体系里最专业的一句话。因为编一个数字的代价，远高于承认不知道。

## 与数据分级的关系

本协议是 `data/source-grading.md` 的操作层。分级规则说「什么级别能进判断」，本协议说「怎么搜、搜到什么程度算够」。

两者配合使用：先用本协议检索，再用分级规则决定哪些能写进结论。
