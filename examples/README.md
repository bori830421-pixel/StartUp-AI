# 样例索引

本目录保存技能的行为样例，用于验证 `docs/verification-guide.md` 中的验收场景是否真的可执行。每个样例包含：输入、缺口判断、完整输出、自检清单。

| 样例 | 场景 | 覆盖能力 | 对应验收行 |
| --- | --- | --- | --- |
| [01](./01-vague-keyword.md) | 只有一个模糊关键词 | 需求与约束收集、创业方向探索 | 第 1 行 |
| [02](./02-zero-budget.md) | 零启动资金 | 零启动资金路径、启动框架与行动计划 | 第 2 行 |
| [03](./03-dynamic-market.md) | 动态市场信息 | 市场与可行性验证 | 第 3 行 |
| [04](./04-selected-direction.md) | 用户已选定方向 | 可行性验证、启动框架与行动计划 | 第 4 行 |
| [05](./05-deck-request.md) | PPT 交付请求 | PPT/PDF 内容整理 | 第 5 行 |
| [06](./06-checkup-report.md) | 体检判定为不建议启动 | 启动条件体检、闸门判定 | 第 6–9 行 |
| [07](./07-coaching-stage.md) | 体检放行后进入 P1 | 启动条件体检、闸门判定、分阶段陪跑 | 第 6、10 行 |

## 使用方式

- 修改 `SKILL.md` 或 `AGENTS.md` 的规则后，用对应样例重跑一次，确认输出仍满足样例末尾的自检清单。
- 新增能力时，先补一个样例，再更新 `docs/capability-index.md` 的状态与样例列。
- 样例中的金额、周期、比例均为示例或估算；标注为「待核实」的内容不得当作事实引用。

## 样例的共同约定

1. 事实、估算、假设、待核实四类信息分开标注。
2. 不出现未标注来源的市场规模、佣金、成本或成功率。
3. 每个样例都以「一个近期行动 + 一个继续或停止指标」收尾。
4. 涉及法律、税务、监管的内容只给核对方向，并提示向所在地专业人士确认。

## 样例之间的关系

02、04、05 是同一条业务线的三个阶段：零资金起步（02）→ 选定方向做验证（04）→ 向投资人呈现（05）。05 的数字与 04 必须一致，这是 `references/output-templates.md` 中「结论、假设、来源和日期保持一致」的可执行检查点。

06 与 07 是一对反例和正例，演示闸门两侧的差别：06 体检不通过，输出停在判断加最小代价出口，没有阶段任务；07 体检通过，直接进入 P1 且只给一个阶段。对照阅读可以看出「不建议启动」和「放行」在输出形态上的区别，而不是只有措辞不同。
