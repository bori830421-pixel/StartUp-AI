# 样例 24：有网，但没有搜索工具

覆盖能力：检索工具缺失兜底、运行时检索
对应验收场景：`docs/verification-guide.md`「检索工具缺失但有网」

本例处理一种最容易被误判成「断网」的情况：**网络是通的，但会话里的搜索工具报配置错误。** 两者都表现为「搜不了」，处理方式却相反——前者往往还能救。

## 输入

> 我在赣州，想开个奶茶店，预算 15 万，要雇 2 个店员。店员一个月工资大概多少？
>
> （场景设定：本会话的搜索工具报错 `DeepSeek search has no API key for "DEEPSEEK_API_KEY"`，但能打开外部网址）

## 一、先判：是没网，还是没工具

报错原文是缺 API key，**这不是网络问题**。判据只有一条：能不能访问任意一个外部 URL。能访问就有救。

所以不做断网降级，先按 `references/search-fallback.md` 试公开端点。这一步的判断很重要——直接宣布「无法检索」，等于把还能查的事丢掉了。

## 二、先测基线，再挑端点

先打开 `https://www.gov.cn/` 确认基线：能打开，说明网络通着，问题只在「没有搜索工具」。这一步定了性质，后面所有判断都挂在它上面。

然后从 `references/search-fallback.md` 的候选池里取一个端点。该文件不排顺序，选哪一个由基线决定。两个技术点必须做对，否则拿到的不是结果：

1. **带浏览器 User-Agent**，只带 UA 还不够——抓 HTML 版端点还要完整的 `Accept` / `Accept-Language` / `Referer` 头和 Cookie 处理器。缺了会拿到 HTTP 202 反爬挑战页（约 14 KB，零结果），看起来像「查到了但没内容」。
2. **拿到 HTML 不算成功。** 要检查返回内容里有没有查询主体的关键词——本例要看到「赣州」「奶茶」「工资」这三个词都出现。

只用一个端点，失败再换。三个端点同时打同一个查询，是三倍预算换同一份信息。

## 三、端点不排顺序，按基线选组

本例的机器能打开政府站，但 DuckDuckGo、Brave、Yahoo 全部 `fetch failed`，说明这是**国内网络**——不是端点坏了，是这条网络到不了境外域名。所以第二轮不在这三个上继续试，改从国内组取一个。

**必应要用国内域名。** `www.bing.com` 会 302 到 `cn.bing.com`，抓取工具多不跟随跨域跳转，第一跳就报错；直连 `cn.bing.com` 才拿到结果。同理，百度网页、搜狗网页、头条搜索都返回 200，但正文区是空的（脚本渲染，抓取工具拿不到），它们属于「空壳页」，不算可用。

**如果只检查状态码，就会把空壳页当检索结果用。** 验证动作是固定的：状态码之外，必须数结果区里查询主体关键词出现了几次。这一条不做，端点兜底就从「补救」变成「造假」。

## 四、拿到了什么，能用到什么程度

国内组的必应返回真实结果页，招聘类摘要里能看到「3–6K」这类区间；微信搜一搜能拿到地方政务号的办事通知。**这两类都只是线索。** 理由三条：

1. 招聘页写的是**招聘报价**，不是实发工资，含绩效、包吃住、试用期打折这些没写进摘要的条件；
2. 摘要来自平台聚合，口径不明，无法核对；
3. 打开原网页多半失败——招聘平台多为 JS 渲染或反爬，摘要能拿到，详情页打不开。

`references/search-fallback.md` 写得很直白：**摘要里的「3-6K」可以当区间线索，不能当「当地实发工资」写进 H2 的分母。**

## 五、打不开原文的那一项

按「半离线」处理：**政策类按「没查到」算，不能用摘要当依据。**

本例要查的是工资区间，属于参数类，处理方式不同——参数类不给数字，给实测方法：

- 去 3 家正在营业的奶茶店，问店员「招不招人、一个月多少」，问 3 个人取区间；
- 看本地招聘公告上写的底薪，那是招聘方公开承诺的口径；
- 赣州最低工资标准按当地人社部门公布的口径核实，这条要打开原文，摘要不算。

顺带说一句：15 万落在 B5（10 万–30 万），奶茶店属于开业即有收入的模式，H2 要走情形 B（净现金流为负）——但工资这个数不落地，H2 现在算不了。

## 六、如果搜索入口全失败

本例的前提是「基线能打开」。另有一种合体情况：**搜索工具缺密钥，两组候选池也全部失败**，这台机器只剩官方站点能直连。

这时不要继续换端点，也不要退回「我再想想办法」。按 `references/search-fallback.md` 的预算收口，然后回到 `references/offline-degradation.md` 第一节的判据：**基线能打开就不是离线**，所以不能宣布「连不上网」，也不能因为搜不到就封顶。正确做法是——政策原文改走官方站点直连，其余项交给用户去查，并在提示里补一句检索记录：

> 补一句记录：我试过这几个搜索入口，都用不了——DuckDuckGo（连不上）、Brave（连不上）、`www.baidu.com/s`（返回 200 但正文没有结果）。不过政府站能打开，所以政策原文这类我仍然可以直连查到，缺的是要搜索才知道去哪找的那几项信息。

三件事必须写清：**试过哪几个入口、各属于哪一类失败、一句修复线索**。少了第一件，用户以为 AI 没试；少了第三件，用户不知道怎么修。这一句不改变结论，只改变他对「为什么查不了」的判断。

## 七、结论

> **搜索工具坏了，但网络是通的，所以这次不是断网降级。** 我用公开端点查到了工资区间线索，但它是招聘摘要口径，**不能直接进 H2 的分母**。
>
> 结论停在：人工成本待实测。这不是「信息不足」——信息不足是没查过；这次查过了，拿到的是线索，缺的是可核对的数。

## 八、下一步唯一动作

三天内做两件事：去 3 家奶茶店各问一次招人工资（取区间中值），同时把赣州最低工资标准从人社部门原文上核一遍。这两个数拿到，H2 才能算。

一句记住的：**端点能救急，但救回来的是线索，不是依据。**
