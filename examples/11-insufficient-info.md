# 样例 11：局部门槛信息不足，仍给当前投入立场

覆盖能力：局部信息不足、主动检索、情景估算、临时投资建议
对应验收场景：`docs/verification-guide.md` 阶段一「体检信息不足」

本例的重点：**不能把某一项硬门槛待核验，写成整份评估无结论。**不给启动放行，也不判整个方向失败；先算可算部分，再说明当前拟议投入是否应继续。

## 输入

> 我想在成都小区附近开一家 30–50 平方米的面馆，启动资金 18 万。我暂时没有工作，可以全职做；家里每月要花 5,000 元。还没定铺位，租金和许可条件都不知道。

## 一、缺失信息分类

| 输入 | 类型 | 处理 |
| --- | --- | --- |
| 预算 18 万、可全职、生活费 5,000 元 | 用户事实 | 直接计算，不重复追问 |
| 店租、同类客单价、岗位工资 | 公开参数 | 按地区主动检索，来源不足时只作情景范围 |
| 桌数、可用座位、翻台率 | 经营模型参数 | 暂无平面图时用面积和座位密度做低、中、高场景 |
| 具体铺位客流、平面布局与食品许可适配 | 本地/官方核验 | 只挂起 H1 点位子项与 H3；签约前核实 |

## 二、检索与情景计算

先按成都和目标片区检索当前的店铺挂牌、同类菜单价格、招聘薪资及当地食品经营许可原文。每条记录注明日期、来源等级和口径。单一挂牌价或招商内容只用于敏感度场景，不写成市场事实。

以情景变量计算，不把缺失值装成事实：

```text
月度门店固定成本 = 月租 R + 人工 W + 水电物业 U + 其他固定项 O
门店保本流水 = 月度门店固定成本 ÷ 贡献率 C
业主现金覆盖流水 = (月度门店固定成本 + 个人生活费 5,000) ÷ C
堂食月流水 = 座位数 × 每座日均周转 × 人均客单 × 营业天数
```

把检索得到的 R、W、客单区间分别代入低、中、高情景；把尚无平面图的座位数和周转率标为模型假设。若保守情景已越过 18 万资金缓冲，建议当前店型先缩小；若结果跨线，结论写为“先不签约，等具体租金、布局和许可核实后再判”。不能因为点位未选就停止计算其他维度。

## 三、局部闸门和当前立场

- H1：经营容量可先算；具体点位需求尚未验证，暂不放行。
- H2：用检索区间与用户生活费计算现金压力；若公开范围仍不足，挂起 H2 的精确结果，但报告已算区间与敏感变量。
- H3：政策原文可查；是否适用于某个铺位的布局与地址，需当地部门确认，签约前不能视为通过。
- S1–S4：先按 18 万、全职投入、能力缺口和装修沉没风险计算；缺资料的部分注明依据，不连带挂起其他项。

> **当前立场：可以继续做低成本的选址比较，但先不付转让费、不签长租、不做装修。面馆方向没有被否定；目前卡的是具体铺位的需求与许可。**

## 四、一个核验动作

先拿到一个候选铺位的平面图和书面租赁条件，连同地址交给当地市场监管部门确认可办理的许可、布局要求与周期；以书面条件替换租金场景后重算 H1、H2、H3。

## 自检

- [x] 公开参数默认检索或做区间情景，没有要求新手先知道租金、客单或座位数
- [x] 用户个人生活支出使用用户回答，没有从网络推断
- [x] 估算、用户事实和现场待核实分开标注
- [x] 局部信息不足没有被写成整份体检无结论或方向失败

- [x] 结尾只有一个能改变判断的核验动作
