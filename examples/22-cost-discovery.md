# 样例 22：固定成本未知时先检索，再做情景估算

覆盖能力：个人约束追问、公开成本检索、H2 情景计算、敏感度
对应验收场景：`docs/verification-guide.md` 阶段一「固定成本三项都说不知道」

本例固定一条规则：**用户不知道租金，不代表评估停住；城市已知就主动检索。用户生活费和经营意愿属于个人信息，仍需问本人。**

## 输入

> 我想在深圳开一家奶茶店，预算 20 万。租金和工资都不知道。

## 一、缺口分流

| 信息 | 分类 | 处理 |
| --- | --- | --- |
| 深圳门店租金、岗位工资 | 公开动态参数 | 自动检索相近商圈、面积和岗位的当前范围 |
| 本人是否守店、要雇几人 | 用户经营选择 | 用选择题问「你准备在店里做什么」；用户答不出时先列替代用工场景 |
| 每月生活费、亏损是否影响基本生活 | 用户个人事实 | 直接问本人，不从网上推断 |
| 具体铺位合同价 | 现场事实 | 线上挂牌只能做范围；签约前换成书面报价 |

## 二、检索与提问并行

方向和城市已经足够启动公开检索，不要求用户先提供租金。检索本地类似面积的商铺挂牌和奶茶岗位薪资，记录链接、日期、面积/岗位口径和来源等级。若只有单一平台或招商来源，只记录为线索；必要时做明确标注的压力测试，不把它当成市场平均价或判断依据。

同时只追问影响个人风险线的问题：

1. 你自己会不会长期在店里做？
2. 每月家用大约多少？
3. 这 20 万全亏掉会不会影响基本生活？

## 三、把区间代入模型

收到个人回答后，不必等待实际租约才继续。将检索范围按低、中、高分别代入：

```text
每月固定经营成本 = 租金区间 + 人工区间 + 水电物业等其他固定项
门店保本流水 = 每月固定经营成本 ÷ 贡献率
业主现金覆盖流水 = (每月固定经营成本 + 用户生活费) ÷ 贡献率
可撑月数 = (20 万 − 一次性开店投入区间) ÷ 每月净现金流出区间
```

贡献率要依据产品售价减原料、包装、损耗和平台扣点计算；还没有配方或渠道信息时，列贡献率区间或反推「每天至少需要多少单」，不能编一个确定净利率。检索到的租金区间不等于本店租金，若两端结果改变 H2，明确把租金列为签约前关键核验项。

## 四、结果和核验动作

如果保守情景下现金消耗已超过用户可承受损失，给出「不建议按当前店型启动」；如果情景跨线，给出「先不签约，拿具体铺位书面条件后复算」；只有情景有缓冲且三项硬门槛均有证据，才考虑放行。

> **租金和工资不知道也能先算出风险范围；实际合同价不确定时，当前行动建议可以是先不签，而不是整份评估没有结论。**

下一步唯一动作：让用户给出候选商圈或铺位链接，替换检索租金范围并重算 H2。

## 自检

- [x] 城市已知，默认检索公开租金与岗位工资
- [x] 个人生活费、风险承受度仍由用户回答
- [x] 检索区间进入低、中、高场景，不冒充实际合同
- [x] 缺少贡献率时改算所需订单量或列出敏感变量，不编净利
- [x] 输出当前行动立场和一个能更新结论的动作
