# A 形态：目录技能

适用：能读写本地文件的宿主。这是首选形态，按需加载只在目录形态里成立。

## 落点

把整个 `dist/startup-guide/` 复制到宿主的技能根目录下，**目录名保持 `startup-guide`**。

常见落点（按宿主文档确认，不要照抄）：

| 宿主 | 用户级 | 项目级 |
| --- | --- | --- |
| WorkBuddy | `~/.workbuddy/skills/` | `<项目>/.workbuddy/skills/` |
| Claude Code | `~/.claude/skills/` | `<项目>/.claude/skills/` |
| 通用 / Codex | `~/.agents/skills/` | `<项目>/.agents/skills/` |

不确定时不用猜：直接问宿主「你的技能（skill）目录在哪里」，它能读出自己配置再回答你。

## 目录名为什么必须是 startup-guide

规范要求 frontmatter 的 `name` 与父目录名一致，且只含小写字母、数字、连字符。仓库叫 `StartUp-AI`，装进去不能用这个名——大写字母不合格，多数宿主会拒绝或改成一个用户找不到的名字。

所以**仓库不是安装单元，`dist/startup-guide/` 才是**。它由 `tools/build_skill.py` 生成，目录名由脚本保证。

## 装完验证

发一句，不加额外提示：

> 我想在小区门口摆摊卖烤肠，预算 3000，帮我看看能不能做。

三条同时成立才算接上：先分模式不直接算钱、出现 H1/H2/H3 中至少两项、结尾是一个当天能做的动作。

## 三个坑

- **不要把仓库根目录整个拷进去。** 会带上 `.venv/`（800 多个 python 文件）和 `tools/wheels/`（27 MB），而且目录名不等于 `name`。
- **不要在 `dist/` 里手改规则。** 每次构建都会覆盖，改了等于没改；要改就改源文件再重建。
- **更新时整目录替换，不要合并。** 删掉的旧文件留在原地会和新版并存，出现两套互相矛盾的规则。先删 `startup-guide/` 再拷新的。
