# 品类卡模板

每张卡对应一个品类。分两部分：**骨架**建卡时写齐；**检索缓存**只在真实评估后补录，遵守 `../source-grading.md` 的分级规则。

## 骨架（必填，不含数字）

| 字段 | 要求 |
| --- | --- |
| 国标门类 | 落到 `../industry-taxonomy.md` 的门类字母，可多个 |
| 登记与许可（H3 起点） | 一般项目还是许可项目；许可项写审批部门与查什么，不给周期定值 |
| 原型候选 | 只用七种原型的标准名，写清主原型与叠加 |
| 典型资金带 | 只写 B1–B6 档位号，不写金额 |
| 模式分叉 | 该品类特有的模式清单，注明影响哪几项（S1 / S4 / H2 / S3） |
| 线上必查项 | 4–6 项，每项是「查什么」不是结论；线下项另注但不占检索预算 |
| 口语识别词 | 用户会怎么说这个方向，命中即归本品类 |
| 检索缓存 | 有则注明范围与复核日期；无则写「无」 |

骨架字段不得出现具体金额、客单、成功率。

## 检索缓存（真实评估后补录）

缓存覆盖的是评估过的**形态**，不是整个品类。写明覆盖范围，未覆盖的形态按无缓存处理。

### 缓存元信息

| 字段 | 内容 |
| --- | --- |
| 缓存范围 | 覆盖哪些形态 |
| 首次采集 | YYYY-MM-DD |
| 最近复核 | YYYY-MM-DD |
| 数据质量自评 | 好、一般、差，并说明原因 |

### 1. 最小可行形态

从轻到重排列，具体到形态（档口、上门、线上、摊位），不是「开个店」这种笼统说法。

### 2. 收入结构

| 项 | 内容 | 级别 |
| --- | --- | --- |

### 3. 成本结构

用占营收的比例，不用绝对金额。必须指出哪一项是刚性的（签了合同就改不了）。

### 4. 现金流节奏

收入到账、主要支出、爬坡期。

### 5. 关键约束

最硬的一项只能有一个，其余按强弱排序。

### 6. 常见死法

每条要有可观察的前兆。

| 死法 | 前兆 | 能否提前发现 |
| --- | --- | --- |

### 7. 合规清单

依据必须给 A 类来源链接；地方差异写明「各地不同，需查当地」。

### 8. 体检要点

H1 怎么转写、H2 爬坡期怎么计、H3 最容易卡哪、S1 最低启动现金含哪几项、S4 通常几分。

### 9. 待核实线索

只放 L4 与未交叉验证的说法，注明不进判断。

### 10. 数据来源

L1–L3 给可点开链接与日期；L4 只写来源类型，不提供入口。
