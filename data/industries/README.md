## 待收录

按普通人实际选择频率排序。先做高频，不做全行业——泛泛覆盖 50 个类目，不如做深 12 个。

| 优先级 | 类目 | 为什么收录 |
| --- | --- | --- |
| 高 | 社区零售（便利店、生鲜、水果） | 投入高、周转要求高，新手误判率最高 |
| 高 | 内容与自媒体 | 零资金首选，但收入结构最不稳定 |
| 高 | 本地服务接单（摄影、设计、代运营） | 技能变现最短路径 |
| 中 | 美容美发美甲 | 预付卡模式，现金流与合规风险特殊 |
| 中 | 教育培训与托管 | 资质门槛高，政策敏感 |
| 中 | 电商与平台店 | 平台规则依赖，需单独讲清流量逻辑 |
| 中 | 宠物服务 | 增长快，但复购与信任门槛特殊 |
| 低 | 汽车后市场 | 投入高，普通人进入门槛偏高 |
| 低 | 婚庆与活动 | 项目制，现金流波动极大 |
| 低 | 健康养生（推拿、健身） | 资质与预付卡双重风险 |

## 收录标准

一个类目值得建档，要同时满足三条：

1. 普通人用不超过 20 万、1 到 2 人就能启动
2. 有至少一项可查的 A 类来源（政策、办事指南）
3. 存在明确的失败模式，且能给出可观察的前兆

不满足第 2 条的类目，即使热门也不建档——没有可靠来源就只能靠编，那正好是本项目要避免的。

## 使用方式

体检时按用户方向匹配档案卡，把它当作结构依据，不当作结论：

- 档案卡的 L1 内容（成本结构、现金流节奏、常见死法）可以直接支撑判断
- L2 内容只能作范围参考，必须提示用户按当地实测
- L3 内容必须提示用户现场核实，不能替代官方查询
- 档案卡不覆盖的内容（如具体位置的客流、具体客户的付费意愿）仍然只能靠用户验证

档案卡不能让体检跳过用户核实。它只是让判断有依据，不是让判断有答案。

## 维护

- 每张卡有复核日期，超期使用时必须提示数据可能过期
- 新增类目前先检索，确认有 A 类来源可查，再建档
- 发现某个数字在多个来源之间冲突时，不取平均，而是标注冲突并说明口径差异
