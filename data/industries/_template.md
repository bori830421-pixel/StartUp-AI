# 行业档案卡模板

每张卡对应一个普通人能做的创业类目。填卡时遵守 `../source-grading.md` 的分级规则。

## 元信息

| 字段 | 内容 |
| --- | --- |
| 类目 | |
| 一句话描述 | |
| 最小资金门槛 | 区间，标 L2 与口径 |
| 人力门槛 | 几人可做 |
| 首次采集 | YYYY-MM-DD |
| 最近复核 | YYYY-MM-DD |
| 数据质量自评 | 好、一般、差，并说明原因 |

## 1. 最小可行形态

一个人或两个人的最简版本是什么。要具体到形态（档口、上门、线上、摊位），不是「开个店」这种笼统说法。

## 2. 收入结构

| 项 | 内容 | 级别 |
| --- | --- | --- |
| 客单价 | | L2 |
| 单量 | | L2 |
| 复购来源 | | L1 |
| 季节性 | | L1 |

## 3. 成本结构

用占营收的比例，不用绝对金额。绝对金额地区差异太大，比例才能跨地区参考。

| 成本项 | 占营收 | 可调性 | 级别 |
| --- | --- | --- | --- |

必须回答一个问题：哪一项是刚性的（签了合同就改不了）。

## 4. 现金流节奏

| 环节 | 节奏 | 说明 |
| --- | --- | --- |
| 收入到账 | | |
| 主要支出 | | |
| 爬坡期 | | 开业到现金流为正需要多久 |

## 5. 关键约束

这个类目最硬的那一项是什么：选址、资质、人力、供应链，还是获客。只能有一个最硬的，其余按强弱排序。

## 6. 常见死法

这是全卡最有价值的一段。不写「如何成功」，只写「通常怎么死」。每条要有可观察的前兆。

| 死法 | 前兆 | 能否提前发现 |
| --- | --- | --- |

## 7. 合规清单

| 事项 | 依据 | 查询入口 | 周期 |
| --- | --- | --- | --- |

依据必须给 A 类来源链接，不能只写法规名称。地方差异必须写明「各地不同，需查当地」。

## 8. 体检要点

这个类目在七维体检里的重点项，以及需要调整的口径。

- H1 客户可达：这个类目的「10 个客户」怎么定义
- H2 现金流断点：爬坡期怎么计入
- H3 合规前置：最容易卡在哪
- S1 资金匹配：最低启动现金包含哪几项
- S4 可逆性：通常几分，为什么

## 9. 待核实线索

只放 L4 内容和未交叉验证的说法，明确标注不能进判断。

| 说法 | 来源 | 为什么不采信 |
| --- | --- | --- |

## 10. 数据来源

| 数据 | 级别 | 来源 | 链接 | 日期 | 备注 |
| --- | --- | --- | --- | --- | --- |

L1 到 L3 必须给可点开的链接。L4 不列链接，只写来源类型——不为不可靠来源提供入口。
