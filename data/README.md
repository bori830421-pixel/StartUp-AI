# 数据层索引

本目录保存体检时引用的外部依据：数据来源怎么分级，以及按类目组织的行业档案卡。

本目录不放方法论（在 `../references/`）、不放样例（在 `../examples/`）。

## 文件清单

| 文件 | 用途 | 状态 |
| --- | --- | --- |
| [source-grading.md](./source-grading.md) | 数据来源分级（A/B/L1–L4）、引用标注要求、利益相关来源的打折规则 | 现行 |
| [archetypes/](./archetypes/) | 生意原型库，七种生意结构各一卡，含识别表 | 7 个原型 |
| [industries/](./industries/) | 行业档案库，一类目一卡，含收录标准、待收录清单与档案模板 | 3 个类目 |

原型库回答「这门生意靠什么赚钱、卡在哪」，行业档案库回答「这个类目的具体成本与死法」。体检时先用原型定位结构，再用行业卡补细节；两者冲突时以实测为准。

## 数据层的两条硬约束

- 档案卡只提供结构依据，不提供结论；标「无可靠数据」的部分改用用户实测，不许补编数字。
- 引用任何数据都必须带级别与来源，L4 内容只能作为待核实线索，不得进入判断依据。

## 新增约定

- 新增类目先按 `source-grading.md` 确认有可查来源，再按 `industries/_template.md` 建卡，最后在 `industries/README.md` 的「已收录」表登记。
- 每张卡必须写复核日期；超期使用时要提示数据可能过期。
- 档案卡控制在建议上限内，单卡超过 200 行时按「结构依据 / 实测清单 / 失败模式」拆成多卡或分节文件。
